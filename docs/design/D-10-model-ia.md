## TL;DR（≤ 25 行，Manager 只读这里）

- **用户说的"重复"，实测比"重复"更严重：两处对同一个问题给出互相矛盾的答案。** `:10000` 实例上，
  `/models` 顶部写「语言模型：**未选择 —— 思维导图功能不可用**」，而同一时刻 `/settings` 写
  「当前生效：**DeepSeek · deepseek-v4-flash**」（两处截图/正文均已抓取，见 §0）。根因：`/models`
  读 `GET /api/models/installed → active.llm`（永远是 `null`，因为在线 provider 根本不进这张表），
  `/settings` 读 `settings['llm.defaultProviderId']`。**两个数据源，一个问题。**
- **`/models` 的「语言模型」Tab 现在装的是 ADR-016 已经砍掉的东西**：4 张 GGUF 下载卡
  （通义千问 3 · 4B「官方默认」/ 8B / 1.7B / Gemma 3 · 4B），引擎全是 `llama.cpp`。
  `/runtime` 里还配套挂着 **7 个 llama.cpp 后端包**。下完没引擎能跑 → **整条线下架**（迁移表 #7 #12 #22）。
- **采纳用户的骨架，但订正一处语义陷阱**：`转写` 下的"本地"= **我们下载并拥有的权重文件**；
  `语言模型` 下的"本地"= **别人装好的一个服务（Ollama/LM Studio），我们只探测**。
  同一个词两种东西 —— 这正是用户在抱怨的那种混淆，**别让「本地」变成新的「模型」**。故 UI 上加副标题逐字区分。
- **判断①「本地 / 在线」是同一列表里的两个分组，不是 Tab、不是筛选器。** 在线组默认展开在上，
  本地组折叠在下且是 **[探测本机]** 按钮而非目录 —— 因为 ADR-016 之后本地侧**根本没有可浏览的清单**
  （只有 2 个候选），拿 Tab 装 2 项既浪费又暗示两侧对等。**用户的骨架作为分类学成立，作为版面权重不成立**，两者我都照顾到了。
- **判断②「GPU 后端包 / 运行时」不算模型，`/runtime` 继续做一级导航的兄弟节点**（§3.2 给了 4 条论证 + 1 条我必须承认的反证）。
  但 `/runtime` 自己也犯了同一个命名病：22 个包里 **12 个（libsimple / sqlite-vec / ffmpeg）与 GPU 加速无关**，
  却统称「加速后端包」→ 页内拆成「转写加速后端」与「功能组件」两区。
- **判断③ 状态词：统一"轴"和"视觉"，不统一"动词"；只有 `使用中` 和 `异常` 必须逐字相同。**
  给在线 API 写「未安装」是在撒谎（没有东西可装）；但「可安装」（后端包）与「未安装」（模型）是同一个槽位说了两个词，必须并成一个。详见 §5 的 5 槽表。
- **约束②（用途下拉必须是已配置 provider 的子集）—— 代码里已经做对了**，我核实到了证据：
  `PurposeBindingsSection.tsx:86` 走 `useLlmConfig()` → `readProviders(settings['llm.providers'])`，
  与「AI 模型」区块的写入键**同一把**；写死的 `LLM_PRESETS` 只喂「+ 添加」按钮。
  **所以这条不是"要去修"，是"要在合并后不许弄丢"** —— 我把它写成不变量（§6.2），并把同一条规则扩到转写侧。
- **但底下埋着一处真的双源**：前端写 `llm.providers`（清单），daemon 的 `resolveConfiguredProvider()`
  **只读** `llm.defaultProviderId` / `llm.defaultModelId` / `llm.baseUrl.<id>`，**从不读 `llm.providers`**
  （`apps/daemon/src/llm/resolve.ts:59-77` 逐行核实）。今天靠前端"两边都写"维持一致。**需 Manager 裁决归并方向**（§8-D1）。
- **whisper 的"墙"已经被前人挡掉一半**：目录 25 个变体 **已按 12 个 `groupId` 收成卡片**（量化在卡内选），
  中文档再按 ADR-011 隐掉 13 个 → 实际只渲染 **8 张卡**。剩下的问题不是数量是**排序与混装**：
  实时流式引擎、离线批量引擎、被 v3 严格支配的 v1/v2 挤在同一列。→ 按**用途**分三组（§4.1）。
- **目录里 `role=vad`(2) 与 `role=punctuation`(1) 三个变体，UI 里完全不可见** ——
  `ROLE_TABS` 只有 `asr`/`llm`（`ModelsPage.tsx:39-42`）。而它们是 Paraformer 标点与 sherpa 流式 VAD 的必需件。→ 迁移表 #10。
- **迁移表 23 条**（§6.1），每条精确到区块 + 文件 + 行号 + 责任 agent。
- **未验证/存疑**：`POST /api/llm/detect` 端点**不存在**（`detectLocalBackends` 只在 mindmap runner 内部调用），
  「本地模型」组的 [探测本机] 按钮**依赖一个还没有的端点**；memo.ac 对照（§7）截至发稿仍在取证中，**已标注**。
- **对其他 agent 的影响**：`architect` 拿 §4/§6 直接实现；`model-mgmt` 需下架 `models-llm.json`、
  放出 vad/punctuation；`gpu-runtime` 需下架 7 个 llama.cpp 包；Manager 需裁决 §8 的 3 条。

### 0.1 ★ 本文最要紧的一条：两处对同一个问题给出相反答案 `[实测]`

同一时刻、同一实例：

```
/models 顶部「当前使用」          /settings →「AI 模型」

│ 转写模型  Whisper base…   │     │ 当前生效: DeepSeek · deepseek-v4-flash│

└──────────────────────────┘

根因 `[读码]`：

- `/models` 的「当前使用 · 语言模型」读 `GET /api/models/installed` 的 `active.llm`
  （`ModelsPage.tsx:177-213`）。`[API]` 该字段实测为 `null`，且**永远会是 `null`** ——
  在线 provider 不是"已安装模型"，不进 `installed` 表。
- `/settings` 的「当前生效」读 `settings['llm.defaultProviderId'] + ['llm.defaultModelId']`

**所以用户看到的不是"两个地方都有模型设置"这么轻的问题，是"一个地方在谎报功能不可用"。**
这条单独就够立项。

### 0.2 「模型」一词今天的四种含义 `[实测 + 读码]`

| # | 位置 | 「模型」在这里指 | 数据源 | 单位 |
|---|---|---|---|---|
| 1 | `/models` → 转写模型 Tab | 要下载到本机的 ASR 权重文件 | `GET /api/models/catalog` `role=asr` | 12 组 / 25 变体 |
| 2 | `/models` → 语言模型 Tab | 要下载到本机的 GGUF 权重文件 | 同上 `role=llm` | 4 组 / 5 变体（**ADR-016 已砍**） |

## §1 信息架构总纲

### 1.1 三条定名规则（后续所有决定都从这三条推出）

> **R1 —「模型」= 会产出内容的那个东西（权重 或 远端服务）。**
> 判据：换掉它，输出的文字/摘要会变。→ ASR 权重、LLM provider+型号 是模型；
> ffmpeg、libsimple、CUDA 运行库**不是**（换掉它们输出一字不变，只是快慢/能不能跑）。

> **R2 —「模型」按用户要它干什么分类，不按它的技术实现分类。**
> 用户脑子里的第一个分叉是「把声音变成字」还是「把字变成摘要/导图」，
> 不是「ggml 还是 onnx」、也不是「role=asr 还是 role=llm」。
> → 顶层两支就是用户给的：**转写** / **语言模型**。

> **R3 — 同一个问题只准有一个答案的出处。**
> 「我现在用的是哪个？」必须只有一个区块回答（§0.1 就是违反它的代价）。

### 1.2 导航树 `[设计]`

```
侧栏（一级）
├─ ＋ 新建捕获
├─ 📄 全部笔记 / ⭐ 星标 / 🎙 录音 / 📁 文件夹        ← 不动
├─ ────────────────
├─ 🧩 模型            /models        ← 一个页面，页内两个 Tab（不是分区、不做子路由）
│   │
│   ├─ 【常驻】当前使用           ← 跨 Tab 常驻在页顶，R3 的唯一出处
│   │      ├ 转写      Whisper base (Q5_1) · 已校验          [更换]
│   │      └ 语言模型   DeepSeek · deepseek-v4-flash          [更换]

│   │      ├ 推荐               Paraformer 中文 / large-v3-turbo 多语种
│   │      ├ 实时字幕组件        sherpa 流式 zh-14M · Silero VAD · 中文标点恢复
│   │      └ ▸ 更多 Whisper 档位（折叠 · 10 组）
│   │
│   └─ Tab 2「语言模型」                                     （= LLM）
│          ├ 在线 AI 模型  ★默认展开   已配置的服务商卡片 + 「+ 添加服务商」
│          │                          副标题：填 API Key 即可，不下载任何东西
│          ├ ▸ 本地模型（折叠）        [探测本机] → Ollama / LM Studio
│          │                          副标题：接上你已经装好的本地服务；我们不再分发本地模型
│          └ 按用途分别配置            对话 / 摘要+导图 / 翻译
│                                     （服务商下拉 = 上面两组的并集，不许再有第二份清单）
│
├─ ⚙ 运行时          /runtime       ← 保持一级；不是模型（§3.2）
│      ├ 你的硬件            GPU / 内存 / CPU / 模型目录剩余
│      ├ 转写加速后端         whisper.cpp × {cpu, cuda, …}
│      └ 功能组件            ffmpeg · 中文分词器 · 向量检索
│
├─ 📋 任务中心        /tasks         ← 不动
└─ ⚙ 设置            /settings
       ├ 通用          语言 · 主题
       ├ 网络代理      模式 · 手动地址 · 测试
       ├ 数据位置      当前目录 · 占用统计 · 更改/移动 · 目录说明
       ├ 关于          契约版本 · 无遥测声明
       └ ↪ 模型与 AI 服务  →「模型」页        ← 一行入口，不是区块

**「模型」是一个页面而不是一个分区（带子路由的分组）** —— 理由三条：

1. **候选项太少撑不起分区。** 合并后转写侧 14 组、语言模型侧最多 11 个服务商。
   给 25 个条目开一个带侧栏的分区，是拿导航层级换空气。
2. **两支之间要能互相看见。** 用户来这一页最常见的目的是"我到底配全了没有"。
   常驻的「当前使用」两行必须同屏 —— 拆成两条路由就同不了屏，`/models/asr` 与
   `/models/llm` 会各自复述一遍，第二天就漂移（`llm.providers` vs `llm.baseUrl.*` 已经是前车之鉴）。
3. **路由改动越小越好。** `/models` 已是既有路由与既有 `nav.models` 词条，
   Tab 状态进 URL query（`?tab=asr|llm`）即可满足 D-05 §1.2「URL 是可分享状态」的约定，
   不需要新增任何路由。

**为什么 Tab（而不是长滚动页两个区块）**：转写侧折叠后仍有 ~14 张卡，语言模型侧
有表单与 Key 输入。两者叠在一页会让"我要配 LLM"的用户先滚过一屏模型卡。
Tab 的代价是"看不见另一边"，而这个代价已经被页顶常驻的「当前使用」抵消掉了。

## §2 判断①：本地 / 在线怎么放

### 2.1 结论

**在同一个列表里做两个分组（Group），不是 Tab、不是筛选器。在线组默认展开且在上；本地组默认折叠且在下。**

### 2.2 用户的骨架成立在哪、不成立在哪

用户给的骨架是：

```
语言模型
├── 本地模型
└── 在线 AI 模型
```

**作为分类学，它 100% 成立** —— 这两个确实就是穷尽的两类，我照原样保留了这两个词。
**作为版面权重，它不成立**，有三条实证理由：

1. **ADR-016 决策 3 已经定了在线是主路径**，本地只保留"复用你已装的"。
   `llm-catalog.ts:22-25` 的注释把这条写得很直白：
   *"用户要的是「和 memo 一样用在线」，界面就不该让本地看起来是默认答案。"*
   两个对等的 Tab 恰恰是在说"这两条路一样正当"。
2. **本地侧没有可浏览的清单。** ADR-016 之后本地只剩 2 个候选（Ollama / LM Studio），
   而且它们不是"目录里的条目"，是"你机器上有没有"的探测结果。
   **拿一个 Tab 装一个二值探测结果，是把按钮包装成了导航。**
3. **Tab 会隐藏一半。** 用户第一次进来必须一眼看到"在线填个 Key 就能用"。
   如果他落在「本地」Tab 上（或不确定该点哪个），他会以为要装东西 —— 这正是 ADR-016 想避免的。

### 2.3 但"分组"必须解决"本地"一词的二义 —— 这是我要订正的一处

| 出现位置 | 「本地」指 | 我们对它做什么 | 失败长什么样 |
|---|---|---|---|
| 转写 → 本机模型 | **一个我们下载并拥有的权重文件** | 下载、校验 SHA-256、删除、量化选档 | 「下载失败」 |
| 语言模型 → 本地模型 | **一个别人装好的常驻服务** | 只探测、只填地址，**不下载不管理** | 「没检测到 Ollama 在运行」 |

同一个词、两种东西、两套失败模式。**如果不处理，「本地」就会变成新的「模型」** ——
用户这次抱怨的就是这个模式。处置：

- 两处**都保留用户给的词**（不发明新术语，术语发明成本比二义更高）；
- 但每处**强制配一句副标题**逐字消歧（文案见 §4.2）；
- 且两处**用不同的主操作动词**：转写侧是 `[下载]`，语言模型本地侧是 `[探测本机]`。
  动词不同，用户 200ms 内就知道这不是同一件事。

### 2.4 转写侧没有「在线」—— 这不对称是对的，不要补齐

R-06 §核实：memo.ac 有 4 个云 ASR 插件（Deepgram / ElevenLabs / Groq / OpenAI），我们零个。
ADR-016 决策 2「本地 ASR 不再扩容」管的是本地扩容，**没有**授权我们去开云 ASR 这条新线。
→ **转写 Tab 不设本地/在线分组**，因为在线那一格现在是空的，画一个空分组只会让人问"是不是还没做完"。
未来若开云 ASR，转写 Tab 按同一模式加一个「在线转写服务」组即可，结构不用改。

## §3 判断②：运行时 / GPU 后端包算不算「模型」

### 3.1 结论

**不算。`/runtime` 继续作为一级导航的兄弟节点，不并进「模型」。**

### 3.2 论证

**论据 1（R1 判据 · 最硬的一条）：换掉它，输出不变。**
把 whisper.cpp 的 CPU 后端换成 CUDA 后端，转出来的字**一模一样**，只是从 23 分钟变成 2 分钟。
把 `ggml-base-q5_1` 换成 `large-v3-turbo`，转出来的字**完全不同**。
→ 前者是性能维度，后者是内容维度。混在一起，用户就没法回答"我转得不准，该换哪个"。

**论据 2：选择的主语不同。**
模型是**用户选**的（"我要中文准一点" → Paraformer）。
后端包是**机器决定**的（有 NVIDIA 卡就 CUDA，没有就 CPU）——
`[实测]` `/runtime` 上 22 个包里 17 个在这台 linux/x64 机器上**永远装不了**（面向别的 OS/架构）。
一个"用户永远不该做选择"的列表，不该和"用户必须做选择"的列表并列在同一分类下。

**论据 3：生命周期不同。**
后端包基本是首启引导时一次性装好（`/onboarding` 第 2 步就是它），之后几个月不碰。
模型是持续调整的（换语言、换精度、腾磁盘）。合并会让高频操作被低频内容淹没。

**论据 4：合并会把"运行时"这个词也带偏。**
`/runtime` 上真正的加速后端只有 whisper.cpp 那 3 个（下架 llama.cpp 之后）。
剩下 12 个是 ffmpeg / 中文分词 / 向量检索 —— 它们连"加速"都不是，更不是模型。
把这一整页塞进「模型」，等于把三类东西压进一个词。

**⚠️ 我必须承认的反证（不藏）：三处真实耦合。**

| 耦合点 | 事实 `[实测]` | 处置 |
|---|---|---|
| 共用磁盘 | `/models` 页尾「磁盘占用」把 `Whisper base` 与 `whispercpp-cpu-linux-x64`、`libsimple`、`sqlite-vec` **列在同一张表里** | ✅ 保持共用一个 `StorageBreakdown` 组件。**磁盘是一个跨域视图，不是一个分类依据** |
| 共用下载机制 | 两者都走 `JOB_KINDS = ['model','backend-pack']`、同一套 SSE、同一个任务中心 | ✅ 保持。这是实现共用，不是概念同类 |
| 共用「使用中」芯片 | `BackendChipState.active` 与模型的 `使用中` 是同一个词 | ✅ **正是 §5 要统一的那一格**。共用状态词恰恰说明它们是"两类东西的同一个生命周期槽位"，不是同一类东西 |

**耦合处必须双向导流**（否则拆开就是甩锅）：

- 模型卡的 fit 徽标若因缺后端而降级（`FitReasonCode` 命中 `cpu_only_slow` 且存在可装的加速包）
  → 卡内一句「装上 CUDA 后端可快约 N 倍」+ `[去运行时]`；
- `/runtime` 装完 whisper.cpp 后端 → 完成态给 `[去模型页挑一个]`（`jobToast.gotoModels` 词条已存在）。

### 3.3 顺带修掉 `/runtime` 页内的同型病

`「加速后端包」`标题下混着三类东西 → 页内拆两区（**不改路由、不改一级导航**）：

```
/runtime
├─ 你的硬件              （不动）
├─ 转写加速后端           whisper.cpp × {cpu | cuda | …}      ← 名副其实
│     └ 说明：换这个只影响快慢，不影响转写结果
└─ 功能组件              ffmpeg/ffprobe · 中文分词器 libsimple · 向量检索 sqlite-vec
      └ 说明：不装也能跑，但对应功能会缺（媒体导入 / 中文搜索 / 语义搜索）
      └ ▸ 不适用于这台机器的 N 个包（折叠，D-09 已实现，保留）
```

**「运行时」这个名字本身**：它是给工程师看的词。建议改成 **「本机组件」**，副标题
「硬件检测 · 加速后端 · 功能组件」。但这动的是一级导航词条（`nav.runtime`）与 D-05 §1.1 的既有骨架，
**我不单方面定，列进 §8-D3 请 Manager 裁决**。路由 `/runtime` 无论如何不改（保住既有链接与 `jobToast.gotoRuntime`）。

## §5 判断③：状态词统一到什么程度

### 5.1 结论

**统一"轴"和"视觉"，不统一"动词"。全域只有两格必须逐字相同：`使用中` 与 `异常`。**

### 5.2 先看今天有几套 `[读码]`

| 域 | 定义处 | 值 | 渲染成的中文 |
|---|---|---|---|
| 模型安装态 | `models.ts:203` `integrity` | `ok / unverified / corrupt / missing_files` | 已校验 / 未校验 / — / — |
| 模型适配度 | `fitness.ts:15-21` `FIT_TIERS` | `recommended / slow_partial / slow_cpu / unsupported / blocked_disk` | 推荐 / 可跑但慢 / 可跑但慢 / 跑不动 / 空间不足 |
| 下载作业 | `jobs.ts:21-30` `JOB_STATES` | `queued / blocked / leased / running / paused / succeeded / failed / cancelled` | 排队中 / 暂时无法继续 / … |
| 作业步骤 | `jobs.ts:43` `JOB_STEPS` | `resolving / downloading / verifying / installing` | 正在选择下载源 / 下载中 / 正在校验完整性 / 正在安装 |
| 后端包芯片 | `BackendChip.tsx:16` | `active / installed / available / not-installed / failed` | **使用中 / 已安装 / 可安装 / 不可用 / 自检失败** |
| LLM 服务商 | `LlmSettingsSection.tsx:164-174` | （无枚举，就地拼串） | **使用中 / 已设置 sk-… / 未设置 Key / 本地，无需 Key** |

### 5.3 为什么"全都统一成一套词"是错的

**因为一个模型同时处在三个正交轴上，不是一个状态机。**
`Whisper large-v3-turbo` 此刻同时是：**未安装**（安装轴）× **可跑但慢**（适配轴）× **未在用**（生效轴）。
把它们压成一个词，必然丢掉两个 —— 而"我该不该装它"恰恰要三个都看。
今天的三个徽标（`FitBadge` / `StatusChip` / 量化档）并存**是对的，不要动**。

**同时，"全都各写各的"也是错的**，有两处硬伤：

- **同一槽位两个词**：后端包写「可安装」，模型写「未安装」。是同一件事（本机没有，可以获取）。
- **同一个词跨域视觉不一致**：`使用中` 在 `/models`（`StatusChip`）、`/runtime`（`BackendChip`）、
  设置（就地拼串）是三套实现。用户扫页面时最想一眼捞出来的就是这个词。

### 5.4 方案：一根**可用性轴**，5 个槽位，**槽位统一 / 措辞按域**

| 槽 | 语义 | 转写模型 / 后端包（要获取的） | 在线 AI 模型（要配置的） | 本地 AI 服务（要探测的） | 视觉 |
|---|---|---|---|---|---|
| 0 | 本机没有，可获取 | **未安装** | **未设置 Key** | **未检测到** | 中性描边 chip |
| 1 | 正在进行 | **下载中→校验中→安装中** | **测试中** | **探测中** | running 脉动，进度条 |
| 2 | 已就绪，未生效 | **已安装** | **已配置** | **已发现** | good 描边 chip |
| 3 | **正在被用** | **使用中** | **使用中** | **使用中** | **accent 实心 chip（全域同一实现）** |
| 4 | **异常** | **异常**（+ 一句因由：文件损坏 / 安装失败 / 自检失败） | **异常**（连接失败 / Key 无效） | **异常**（服务已离线） | serious 实心 chip |

**规则（给 `architect` 的硬约束）**

- **R-S1** 槽 3 `使用中` 与槽 4 `异常` **全域逐字相同、组件相同**（提升为
  `components/common/` 的单一实现，D-05 §3.3 的提升协议）。用户只想快速回答两个问题：
  *"现在在用哪个？"* 和 *"哪里坏了？"* —— 这两个词是那两个问题的答案，不许有方言。
- **R-S2** 槽 0/1/2 **按域用各自的动词**。给在线 API 写「未安装」是**撒谎**——没有东西可装；
  给 Ollama 写「未安装」更糟——它可能装了只是没运行。**准确 > 整齐。**
- **R-S3** 后端包的 `available` **改词为「未安装」**，与模型对齐（同槽同词）。
  今天的「可安装」是同一槽位的第二个说法。
- **R-S4** `blocked`（等依赖）**不进槽 4，不画红** —— 沿用 D-09 已定的结论，
  它进槽 1 并配文「暂时无法继续，条件满足后自动继续」。
- **R-S5** 适配度轴（`FIT_TIERS`：推荐 / 可跑但慢 / 跑不动 / 空间不足）**与可用性轴并存，不合并**，
  且**只出现在转写 Tab** —— 在线 AI 模型没有"跑不跑得动"这回事（跑在别人机器上）。
- **R-S6** `DownloadRow.tsx:18-23` 的本地 `STEP_LABEL` 表与 i18n `progress.*` 是**同四个词的两份**，
  合并为一份（i18n 为准）。这就是"该复用的地方复用"的字面执行。

### 6.2 三条必须写进代码注释的不变量

> **INV-1（约束②，已成立，不许弄丢）**
> 「按用途分别配置」的服务商下拉 **⊆** 已配置服务商清单。
> 今日证据：`PurposeBindingsSection.tsx:86` → `useLlmConfig()` → `llm-catalog.ts:79-106`
> → `readProviders(settings['llm.providers'])`，与「AI 模型」区块写入的 `LLM_PROVIDERS_KEY`
> （`settings/api.ts:131`）**是同一把键**；写死的 `LLM_PRESETS` 只喂「+ 添加」按钮，
> 经 `availablePresets` 过滤掉已配置项。**合并到同一 Tab 之后必须保持这条**，
> 并加一条测试：任取一个 purpose 的下拉项集合 ⊆ 卡片列表 id 集合。

> **INV-2（转写侧的同型规则，**也已经做对了**）**
> 「当前使用 · 转写」的可选项 **⊆ 已安装模型**，**不是**整个目录。
> 今日证据：`components/common/AsrModelPicker.tsx:72-75` 从 `GET /api/models/installed`
> 取数并 `filter(m => m.role === 'asr' && m.integrity !== 'missing_files')`，
> 一个都没装时给"去安装"而不是一个空下拉。**`/models` 的 `[更换]` 必须复用这个组件**——
> 新写一个最容易犯的错就是"从 catalog 里选"，那会让用户选中一个没下载的模型然后转写报错。
> **顺带**：`TranscribeOptions` 在 `/capture` 与「重新转写」处未传 `showModel`，
> 建议一并露出（同一个组件，零新增代码）。

> **INV-3（同一问题一个出处）**
> `使用中` 这个事实在整个应用里只准由页顶「当前使用」区块**权威渲染**一次。
> 卡片上的 `使用中` 芯片是它的**镜像**，必须由同一份 query 数据推导，不得各自计算。
