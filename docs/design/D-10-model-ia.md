## TL;DR（≤ 25 行，Manager 只读这里）

- **"重复"实测比重复更糟：两处对同一问题给出相反答案。** `:10000` 上 `/models` 写「语言模型：**未选择——思维导图功能不可用**」，同一时刻 `/settings` 写「当前生效：**DeepSeek**」。根因：前者读 `active.llm`（**永远 `null`**，在线 provider 不进 `installed` 表），后者读 `llm.defaultProviderId`。**一处在谎报功能不可用**（§0.1）。
- **`/models` 的「语言模型」Tab 装的是 ADR-016 已砍掉的东西**：4 张 GGUF 下载卡（Qwen3 4B「官方默认」/8B/1.7B、Gemma3），引擎全是 `llama.cpp`；`/runtime` 还配套挂 **7 个 llama.cpp 包**且现在点得动。下完没引擎能跑 → **整条线下架**（#7 #12 #22）。
- **「模型」今天有 5 种含义**（ASR 权重 / GGUF 权重 / 二进制后端包 / 远端 HTTP 服务 / 型号字符串，§0.2）。定名三规则：**R1 换掉它输出会变的才叫模型**（→ ffmpeg、CUDA 库不是）；**R2 按用户要它干什么分类**；**R3 同一问题只准一个出处**。
- **导航树：`模型` = 一个页面 `/models`，页内两 Tab（转写 / 语言模型）+ 页顶跨 Tab 常驻「当前使用」两行，不开子路由**（§1.2 三条理由）。
- **判断①「本地/在线」= 同一列表里两个分组，不是 Tab、不是筛选器。** 在线默认展开在上；本地折叠在下且是 **[探测本机] 按钮**而非目录 —— ADR-016 之后本地侧**根本没有可浏览的清单**（2 个候选）。**用户的骨架作分类学 100% 成立，作版面权重不成立**，两者都照顾了（§2）。
- **顺带订正一处语义陷阱**：转写下的"本地"= 我们下载并拥有的权重；语言模型下的"本地"= 别人装好的服务、我们只探测。同词两义 —— **别让「本地」变成新的「模型」**。保留用户给的词，但强制配副标题 + 用不同动词（`[下载]` vs `[探测本机]`）。
- **判断②「GPU 后端包/运行时」不算模型**，`/runtime` 继续做一级导航兄弟节点（§3.2：4 条论证 + 3 条我承认的耦合反证 + 双向导流）。但它自己犯同一个病：22 个包里 **12 个（libsimple/sqlite-vec/ffmpeg）与 GPU 加速无关**却统称「加速后端包」→ 页内拆「转写加速后端」+「功能组件」。
- **判断③ 状态词：统一"轴"与"视觉"，不统一"动词"；全域只有 `使用中` 与 `异常` 必须逐字相同**（§5.4 五槽表）。给在线 API 写「未安装」是撒谎（没东西可装）；但后端包「可安装」与模型「未安装」是同槽位两个词，必须并成一个。`FIT_TIERS` 是独立轴，不合并。
- **约束②（用途下拉 ⊆ 已配置 provider）代码里已经做对了**：`PurposeBindingsSection.tsx:86` → `useLlmConfig()` → `readProviders(settings['llm.providers'])`，与「AI 模型」写入**同一把键**；`LLM_PRESETS` 只喂「+ 添加」。**转写侧同型规则也已做对**（`AsrModelPicker` 只列 installed）。→ 不是"去修"，是"合并后不许弄丢"，写成 INV-1/INV-2 + 测试。
- **whisper 的"墙"已被挡掉一半**：25 变体已按 12 个 `groupId` 收成卡片 + ADR-011 隐掉 13 个 → **实渲染 8 张**。剩下的是**排序与混装** → 按用途分三组（推荐 / 实时字幕组件 / ▸更多档位）+ 档内按 `speedClass` 分快/均衡/高质量 + `superseded` 折叠成 `2 (+2)`（§4.1）。
- **目录里 `role=vad`(2) + `role=punctuation`(1) 在 UI 里完全不可见**（`ROLE_TABS` 只有 asr/llm），而它们是 sherpa 流式的 VAD 与 Paraformer 的标点，**是链路必需件** —— 不是分类问题，是**功能缺件**（#10）。
- **`model-mgmt` 新数据层 4 条约束已逐条核实并采纳**：`speedClass`（目录常量）与 `fitness.speedTier`（按机器算）**不许在 UI 上都叫"速度"**（R-M1）；`superseded` 当折叠钩子；provider 三桶 + **只对 4 家给「刷新模型列表」**（其余 20 家人工转录、无端点，显示 `checkedAt`）；表单由 `configFieldKeys` 驱动（ollama 无 apiKey、mistralai baseUrl 只读）；出厂 `configured: []` 配完整空状态（§4.2.2）。
- **但我订正其中一条**：空档位不能写"该档暂无中文模型" —— `languages:['multi']` 的 whisper **是支持中文的**（ADR-013 原话）。**R-M2：语言维度不许按 `languages` 排他筛选，`multi` 必须落进每个语言格子**；"中文行不行"由 `notRecommendedForLanguage`（实测质量）回答。另：**`en × quality` 也是空的**，这格没被提到。
- 🚨 **合并前必须先拆的雷（§8-D1，最急）**：daemon 靠**硬编码 id** 分派协议（`=== 'anthropic'`，`llm/resolve.ts:89`），而新目录 id 是 **`claude`**（另有 `zhipuai`/`aliyun`/`siliconcloud` 三处不一致），且它**从不读** `llm.providers`。**一旦改吃 24 家目录，Anthropic 会静默落到 OpenAI 兼容分支坏掉。** → 分派改吃 `kind`，排在 P1 之前（P0.5）。
- **迁移表 29 条**（§6.1，每条到区块 + 文件:行 + 责任 agent）；分 **P0 止血 / P0.5 拆雷 / P1 搬家 / P2 补件** 四批（§9）。
- **memo.ac 取证已回（§7），三条改变了论证强度**：① 它也把「模型」按用途拆成并列的 **`语言模型`/`转写设置`/`语音合成`** 三个设置项，**用户的骨架被独立验证了一次**；② 它的 LLM **完全不分本地/在线**（只靠描述文字暗示），置顶 6 家数组与我们逐字相同 —— 判断①**夹在它与用户骨架中间且有理由**；③ 它**没有集中的用途矩阵**（4 个功能 4 份清单 4 个端点，翻译还自带一份），**我们的 INV-1 结构优于它，别改回去**。
- **§7 里我兑现了一句自我打脸**：它的 ASR 分组键是**语言**不是体积 —— 重新论证后结论仍是 `speedClass`，因为它 27 条真跨 6 种语言，我们 12 组里 **8 组是 `multi`**，语言在我们这儿分不开东西。但采纳它两点：**默认给筛过的视野**（≈ ADR-011）与**折叠组**。

## §1 信息架构总纲

### 1.1 三条定名规则（后续所有决定都从这三条推出）

> **R1 —「模型」= 会产出内容的那个东西（权重 或 远端服务）。**
> 判据：换掉它，输出的文字/摘要会变。→ ASR 权重、LLM provider+型号 是模型；
> ffmpeg、libsimple、CUDA 运行库**不是**（换掉它们输出一字不变，只是快慢/能不能跑）。

> **R2 —「模型」按用户要它干什么分类，不按它的技术实现分类。**
> 用户脑子里的第一个分叉是「把声音变成字」还是「把字变成摘要/导图」，
> 不是「ggml 还是 onnx」、也不是「role=asr 还是 role=llm」。
> → 顶层两支就是用户给的：**转写** / **语言模型**。

> **R3 — 同一个问题只准有一个答案的出处。**
> 「我现在用的是哪个？」必须只有一个区块回答（§0.1 就是违反它的代价）。

**「模型」是一个页面而不是一个分区（带子路由的分组）** —— 理由三条：

1. **候选项太少撑不起分区。** 合并后转写侧 14 组、语言模型侧最多 11 个服务商。
   给 25 个条目开一个带侧栏的分区，是拿导航层级换空气。
2. **两支之间要能互相看见。** 用户来这一页最常见的目的是"我到底配全了没有"。
   常驻的「当前使用」两行必须同屏 —— 拆成两条路由就同不了屏，`/models/asr` 与
   `/models/llm` 会各自复述一遍，第二天就漂移（`llm.providers` vs `llm.baseUrl.*` 已经是前车之鉴）。
3. **路由改动越小越好。** `/models` 已是既有路由与既有 `nav.models` 词条，
   Tab 状态进 URL query（`?tab=asr|llm`）即可满足 D-05 §1.2「URL 是可分享状态」的约定，
   不需要新增任何路由。

**为什么 Tab（而不是长滚动页两个区块）**：转写侧折叠后仍有 ~14 张卡，语言模型侧
有表单与 Key 输入。两者叠在一页会让"我要配 LLM"的用户先滚过一屏模型卡。
Tab 的代价是"看不见另一边"，而这个代价已经被页顶常驻的「当前使用」抵消掉了。

## §2 判断①：本地 / 在线怎么放

### 2.1 结论

**在同一个列表里做两个分组（Group），不是 Tab、不是筛选器。在线组默认展开且在上；本地组默认折叠且在下。**

### 2.2 用户的骨架成立在哪、不成立在哪

用户给的骨架是：

```
语言模型
├── 本地模型
└── 在线 AI 模型
```

**作为分类学，它 100% 成立** —— 这两个确实就是穷尽的两类，我照原样保留了这两个词。
**作为版面权重，它不成立**，有三条实证理由：

1. **ADR-016 决策 3 已经定了在线是主路径**，本地只保留"复用你已装的"。
   `llm-catalog.ts:22-25` 的注释把这条写得很直白：
   *"用户要的是「和 memo 一样用在线」，界面就不该让本地看起来是默认答案。"*
   两个对等的 Tab 恰恰是在说"这两条路一样正当"。
2. **本地侧没有可浏览的清单。** ADR-016 之后本地只剩 2 个候选（Ollama / LM Studio），
   而且它们不是"目录里的条目"，是"你机器上有没有"的探测结果。
   **拿一个 Tab 装一个二值探测结果，是把按钮包装成了导航。**
3. **Tab 会隐藏一半。** 用户第一次进来必须一眼看到"在线填个 Key 就能用"。
   如果他落在「本地」Tab 上（或不确定该点哪个），他会以为要装东西 —— 这正是 ADR-016 想避免的。

### 2.3 但"分组"必须解决"本地"一词的二义 —— 这是我要订正的一处

| 出现位置 | 「本地」指 | 我们对它做什么 | 失败长什么样 |
|---|---|---|---|
| 转写 → 本机模型 | **一个我们下载并拥有的权重文件** | 下载、校验 SHA-256、删除、量化选档 | 「下载失败」 |
| 语言模型 → 本地模型 | **一个别人装好的常驻服务** | 只探测、只填地址，**不下载不管理** | 「没检测到 Ollama 在运行」 |

同一个词、两种东西、两套失败模式。**如果不处理，「本地」就会变成新的「模型」** ——
用户这次抱怨的就是这个模式。处置：

- 两处**都保留用户给的词**（不发明新术语，术语发明成本比二义更高）；
- 但每处**强制配一句副标题**逐字消歧（文案见 §4.2）；
- 且两处**用不同的主操作动词**：转写侧是 `[下载]`，语言模型本地侧是 `[探测本机]`。
  动词不同，用户 200ms 内就知道这不是同一件事。

### 2.4 转写侧没有「在线」—— 这不对称是对的，不要补齐

R-06 §核实：memo.ac 有 4 个云 ASR 插件（Deepgram / ElevenLabs / Groq / OpenAI），我们零个。
ADR-016 决策 2「本地 ASR 不再扩容」管的是本地扩容，**没有**授权我们去开云 ASR 这条新线。
→ **转写 Tab 不设本地/在线分组**，因为在线那一格现在是空的，画一个空分组只会让人问"是不是还没做完"。
未来若开云 ASR，转写 Tab 按同一模式加一个「在线转写服务」组即可，结构不用改。

## §3 判断②：运行时 / GPU 后端包算不算「模型」

### 3.1 结论

**不算。`/runtime` 继续作为一级导航的兄弟节点，不并进「模型」。**

### 3.2 论证

**论据 1（R1 判据 · 最硬的一条）：换掉它，输出不变。**
把 whisper.cpp 的 CPU 后端换成 CUDA 后端，转出来的字**一模一样**，只是从 23 分钟变成 2 分钟。
把 `ggml-base-q5_1` 换成 `large-v3-turbo`，转出来的字**完全不同**。
→ 前者是性能维度，后者是内容维度。混在一起，用户就没法回答"我转得不准，该换哪个"。

**论据 2：选择的主语不同。**
模型是**用户选**的（"我要中文准一点" → Paraformer）。
后端包是**机器决定**的（有 NVIDIA 卡就 CUDA，没有就 CPU）——
`[实测]` `/runtime` 上 22 个包里 17 个在这台 linux/x64 机器上**永远装不了**（面向别的 OS/架构）。
一个"用户永远不该做选择"的列表，不该和"用户必须做选择"的列表并列在同一分类下。

**论据 3：生命周期不同。**
后端包基本是首启引导时一次性装好（`/onboarding` 第 2 步就是它），之后几个月不碰。
模型是持续调整的（换语言、换精度、腾磁盘）。合并会让高频操作被低频内容淹没。

**论据 4：合并会把"运行时"这个词也带偏。**
`/runtime` 上真正的加速后端只有 whisper.cpp 那 3 个（下架 llama.cpp 之后）。
剩下 12 个是 ffmpeg / 中文分词 / 向量检索 —— 它们连"加速"都不是，更不是模型。
把这一整页塞进「模型」，等于把三类东西压进一个词。

**⚠️ 我必须承认的反证（不藏）：三处真实耦合。**

| 耦合点 | 事实 `[实测]` | 处置 |
|---|---|---|
| 共用磁盘 | `/models` 页尾「磁盘占用」把 `Whisper base` 与 `whispercpp-cpu-linux-x64`、`libsimple`、`sqlite-vec` **列在同一张表里** | ✅ 保持共用一个 `StorageBreakdown` 组件。**磁盘是一个跨域视图，不是一个分类依据** |
| 共用下载机制 | 两者都走 `JOB_KINDS = ['model','backend-pack']`、同一套 SSE、同一个任务中心 | ✅ 保持。这是实现共用，不是概念同类 |
| 共用「使用中」芯片 | `BackendChipState.active` 与模型的 `使用中` 是同一个词 | ✅ **正是 §5 要统一的那一格**。共用状态词恰恰说明它们是"两类东西的同一个生命周期槽位"，不是同一类东西 |

**耦合处必须双向导流**（否则拆开就是甩锅）：

- 模型卡的 fit 徽标若因缺后端而降级（`FitReasonCode` 命中 `cpu_only_slow` 且存在可装的加速包）
  → 卡内一句「装上 CUDA 后端可快约 N 倍」+ `[去运行时]`；
- `/runtime` 装完 whisper.cpp 后端 → 完成态给 `[去模型页挑一个]`（`jobToast.gotoModels` 词条已存在）。

### 3.3 顺带修掉 `/runtime` 页内的同型病

`「加速后端包」`标题下混着三类东西 → 页内拆两区（**不改路由、不改一级导航**）：

```
/runtime
├─ 你的硬件              （不动）
├─ 转写加速后端           whisper.cpp × {cpu | cuda | …}      ← 名副其实
│     └ 说明：换这个只影响快慢，不影响转写结果
└─ 功能组件              ffmpeg/ffprobe · 中文分词器 libsimple · 向量检索 sqlite-vec
      └ 说明：不装也能跑，但对应功能会缺（媒体导入 / 中文搜索 / 语义搜索）
      └ ▸ 不适用于这台机器的 N 个包（折叠，D-09 已实现，保留）
```

**「运行时」这个名字本身**：它是给工程师看的词。建议改成 **「本机组件」**，副标题
「硬件检测 · 加速后端 · 功能组件」。但这动的是一级导航词条（`nav.runtime`）与 D-05 §1.1 的既有骨架，
**我不单方面定，列进 §8-D3 请 Manager 裁决**。路由 `/runtime` 无论如何不改（保住既有链接与 `jobToast.gotoRuntime`）。

> （`ModelsPage.tsx:39-42`）→ **今天用户没有任何途径装上它们**，而 sherpa 流式没有 VAD 不工作、
> Paraformer 没有标点会吐一整段无标点文字。这不是"分类问题"，是"功能缺件"。

### 4.1.1 ★ 两个"速度"必须在 UI 上分开说 —— 否则就是 `installPath` 事故的复现

`[读码]` `packages/shared/src/models.ts:113-142` 把这件事写得很清楚，我照单采纳：

| | `ModelEntry.speedClass` | `FitResult.speedTier`（+ `speedSource`） |
|---|---|---|
| 值 | `fast` / `balance` / `quality` | `fast` / `moderate` / `slow` / `very_slow` / `unknown` |
| 是什么 | **目录常量**，按模型体积人工分档，**与你的机器无关** | **按你这台机器算出来的**，带 `speedSource` 说明是本机实测 / 参考机 / 未知 |
| 谁给的 | manifest 里写死 | daemon 用硬件快照算 |
| UI 词 | **「档位」**：快 / 均衡 / 高质量 | **「在你的机器上」**：1 小时音频约 23 分钟（参考机实测） |

**硬约束 R-M1：UI 上不许把这两个都叫"速度"。**
一个 `CatalogVariant` 同时带着 `v.speedClass` 与 `v.fitness.speedTier` ——
两个都写「速度：快」，用户没法知道哪个是承诺、哪个是估计。
→ **档位当分组/筛选器用（左侧或顶部的三个按钮），机器估计当卡内的一行说明文字**，位置都不重叠。
且 `speedSource === 'none'` 时**不写数字**，写「速度未测量」（现状已如此，保持）。

### 4.1.2 ★ `superseded` 是折叠钩子，不是隐藏

`[API]` 实测 `multi × quality` 有 **4 组**（large-v1 / v2 / v3 / v3-turbo），
其中 `large-v1` 与 `large-v2` 的 `tags` 里带 **`superseded`**。

→ **正式采纳这个机制**：`speedClass` 分档下，带 `superseded` 的**不平铺**，
收进一行 `▸ 已被新版本取代的 N 个`。显示成 **`2 (+2)`** 而不是 4 张平铺卡。

**为什么不是直接删掉**：复现旧结果、跑对照实验是真实需求，而且我们已经把它们放进过目录 ——
悄悄消失比折叠更让人困惑。**折叠 = 我们表态"别选这个"，删除 = 我们替用户做决定。**

### 4.1.3 ⚠️ 空档位的兜底文案 —— 但我要订正一个说法

`[API]` 我实测了 `语言 × speedClass` 的组数矩阵：

| | fast | balance | quality |
|---|---|---|---|
| `zh`（专为中文训练） | **2**（sherpa 流式 / Paraformer） | **0** | **0** |
| `multi`（多语种） | 2 | 2 | 4（其中 2 个 `superseded`） |
| `en`（仅英文） | 2 | 2 | **0** |

`zh × balance` 与 `zh × quality` 确实是空的 —— 但 **`en × quality` 也是空的**（这一格没被提到）。

**⚠️ 我不同意"该档暂无中文模型"这个兜底文案，它会误导用户。**
`languages: ['multi']` 的 whisper 模型**是支持中文的** —— ADR-013 的原话就是
「需要逐字对齐或中英混排排版时可一键切回 Whisper large-v3-turbo」。
说"暂无中文模型"等于告诉中文用户"你没有高质量选项"，**而他明明有**。

**所以：**

> **R-M2：语言维度不许按 `languages` 数组做排他筛选。**
> `multi` 必须落进**每一个**语言格子。真正的"这个模型中文行不行"由现有的
> `fitness.notRecommendedForLanguage`（ADR-011，**按实测质量**）回答，不由 manifest 的
> `languages` 数组回答。今天的实现就是这么做的（`:10000` 上中文档仍然渲染 large-v3-turbo），**别改坏它**。

若坚持画二维矩阵，空格子的文案必须回答"为什么空"和"那该选什么"两问：

```
中文 · 高质量
┌─────────────────────────────────────────────────────────────────────┐
│ 没有专为中文训练的高质量模型 —— 这不是加载失败。                        │
│ 中文的专用模型（Paraformer / sherpa 流式）都在「快」档，              │
│ 而它们已经是中文场景下最快最准的组合（1 小时录音约 43 秒）。             │
│ 要更高的准确率，请用多语种档的 Whisper large-v3-turbo：                │
│ 它支持中文，代价是慢很多（同一段录音约 23 分钟）。   [看多语种·高质量]   │
└─────────────────────────────────────────────────────────────────────┘
```

`en × quality` 同理：指向 `multi × quality`，并说明"英文用多语种模型没有质量损失"。

## §5 判断③：状态词统一到什么程度

### 5.1 结论

**统一"轴"和"视觉"，不统一"动词"。全域只有两格必须逐字相同：`使用中` 与 `异常`。**

### 5.2 先看今天有几套 `[读码]`

| 域 | 定义处 | 值 | 渲染成的中文 |
|---|---|---|---|
| 模型安装态 | `models.ts:203` `integrity` | `ok / unverified / corrupt / missing_files` | 已校验 / 未校验 / — / — |
| 模型适配度 | `fitness.ts:15-21` `FIT_TIERS` | `recommended / slow_partial / slow_cpu / unsupported / blocked_disk` | 推荐 / 可跑但慢 / 可跑但慢 / 跑不动 / 空间不足 |
| 下载作业 | `jobs.ts:21-30` `JOB_STATES` | `queued / blocked / leased / running / paused / succeeded / failed / cancelled` | 排队中 / 暂时无法继续 / … |
| 作业步骤 | `jobs.ts:43` `JOB_STEPS` | `resolving / downloading / verifying / installing` | 正在选择下载源 / 下载中 / 正在校验完整性 / 正在安装 |
| 后端包芯片 | `BackendChip.tsx:16` | `active / installed / available / not-installed / failed` | **使用中 / 已安装 / 可安装 / 不可用 / 自检失败** |
| LLM 服务商 | `LlmSettingsSection.tsx:164-174` | （无枚举，就地拼串） | **使用中 / 已设置 sk-… / 未设置 Key / 本地，无需 Key** |

### 5.3 为什么"全都统一成一套词"是错的

**因为一个模型同时处在三个正交轴上，不是一个状态机。**
`Whisper large-v3-turbo` 此刻同时是：**未安装**（安装轴）× **可跑但慢**（适配轴）× **未在用**（生效轴）。
把它们压成一个词，必然丢掉两个 —— 而"我该不该装它"恰恰要三个都看。
今天的三个徽标（`FitBadge` / `StatusChip` / 量化档）并存**是对的，不要动**。

**同时，"全都各写各的"也是错的**，有两处硬伤：

- **同一槽位两个词**：后端包写「可安装」，模型写「未安装」。是同一件事（本机没有，可以获取）。
- **同一个词跨域视觉不一致**：`使用中` 在 `/models`（`StatusChip`）、`/runtime`（`BackendChip`）、
  设置（就地拼串）是三套实现。用户扫页面时最想一眼捞出来的就是这个词。

### 5.4 方案：一根**可用性轴**，5 个槽位，**槽位统一 / 措辞按域**

| 槽 | 语义 | 转写模型 / 后端包（要获取的） | 在线 AI 模型（要配置的） | 本地 AI 服务（要探测的） | 视觉 |
|---|---|---|---|---|---|
| 0 | 本机没有，可获取 | **未安装** | **未设置 Key** | **未检测到** | 中性描边 chip |
| 1 | 正在进行 | **下载中→校验中→安装中** | **测试中** | **探测中** | running 脉动，进度条 |
| 2 | 已就绪，未生效 | **已安装** | **已配置** | **已发现** | good 描边 chip |
| 3 | **正在被用** | **使用中** | **使用中** | **使用中** | **accent 实心 chip（全域同一实现）** |
| 4 | **异常** | **异常**（+ 一句因由：文件损坏 / 安装失败 / 自检失败） | **异常**（连接失败 / Key 无效） | **异常**（服务已离线） | serious 实心 chip |

**规则（给 `architect` 的硬约束）**

- **R-S1** 槽 3 `使用中` 与槽 4 `异常` **全域逐字相同、组件相同**（提升为
  `components/common/` 的单一实现，D-05 §3.3 的提升协议）。用户只想快速回答两个问题：
  *"现在在用哪个？"* 和 *"哪里坏了？"* —— 这两个词是那两个问题的答案，不许有方言。
- **R-S2** 槽 0/1/2 **按域用各自的动词**。给在线 API 写「未安装」是**撒谎**——没有东西可装；
  给 Ollama 写「未安装」更糟——它可能装了只是没运行。**准确 > 整齐。**
- **R-S3** 后端包的 `available` **改词为「未安装」**，与模型对齐（同槽同词）。
  今天的「可安装」是同一槽位的第二个说法。
- **R-S4** `blocked`（等依赖）**不进槽 4，不画红** —— 沿用 D-09 已定的结论，
  它进槽 1 并配文「暂时无法继续，条件满足后自动继续」。
- **R-S5** 适配度轴（`FIT_TIERS`：推荐 / 可跑但慢 / 跑不动 / 空间不足）**与可用性轴并存，不合并**，
  且**只出现在转写 Tab** —— 在线 AI 模型没有"跑不跑得动"这回事（跑在别人机器上）。
- **R-S6** `DownloadRow.tsx:18-23` 的本地 `STEP_LABEL` 表与 i18n `progress.*` 是**同四个词的两份**，
  合并为一份（i18n 为准）。这就是"该复用的地方复用"的字面执行。

## §7 与 memo.ac 对照

`[取证]` 取证已返回。以下全部来自 `/root/memo-forensics/` 的 memo.ac v1.7.5 解包产物
（渲染层 bundle 的字面量数组 + `locales/zh-CN.json` + `presets/whisper-models.js` +
`plugins/extra-transcription-plugins.json`）。**只提取结构与标签串，未复制任何源码。**

### 7.1 它的「模型」根本没有一个家

`[取证]` 侧栏一级只有 6 项：**首页 → 批量任务(Pro) → 全部内容 → 笔记 → 应用 → 回收站**。
**「设置」不在侧栏**，是一个**模态框**，左侧图标栏 12 项，顺序（字面量数组求值）：

> 通用设置 → **空间管理**(第 2 项 ✅ 与 ADR-016 里用户的记忆完全吻合) → **语言模型** → 提示词 →
> **转写设置** → 翻译设置 → **语音合成** → 三方集成 → 代理设置 → 权限设置(非 Win) → 实验室 → Memo Pro

**★ 最有价值的一条：它把「模型」按用途拆成了三个并列的设置项 —— `语言模型` / `转写设置` / `语音合成`，
而不是收进一个叫「模型」的容器。** 这正是用户给的骨架的上半截（转写 ‖ 语言模型），
**独立地被另一个产品验证了一次**。§1.1 的 R2（按用途分类，不按实现分类）因此不只是我的偏好。

**但它止步于此，代价也明显**：三个用途各在一个设置分页里，**没有任何一处能同时回答
"我转写用什么 + 我 AI 用什么"**。我们的页顶常驻「当前使用」两行（§4.1）就是补这个 —— 
**我们比它多一步，不是少一步。**

### 7.2 ASR 的 47 条墙：它用**两层**挡，而且第一层是"引擎"不是"模型"

`[取证]` 47 = whisper 15（`whisper-models.js`）+ sherpa/parakeet/funasr 32（`extra-transcription-plugins.json` 的 `asr` 类）。逐条核对吻合。

| 层 | 做法 | 标签串 |
|---|---|---|
| **L1 引擎选择器** | 顶层给的是**一个引擎下拉**（一次只选一个引擎），未安装的引擎置灰；旁边一个「管理引擎」按钮跳到 设置→三方集成 | `transcription.select engine`=「选择引擎」、「管理引擎」 |
| **L1.5 引擎管理页** | 引擎卡片分**两个可折叠组** | **「本地插件」**（whisper / sherpa-onnx / funasr / parakeet）· **「在线插件」**（Deepgram / ElevenLabs / Groq / OpenAI Whisper） |
| **L2 单引擎内的模型列表** | 一个**语言下拉** + 按语言分段的小标题；下拉默认值是 **`multi`（多语种）**，另有「全部模型」 | `model.available models`=「可用模型」；`model.all models`/`multi language`/`only english`/`only chinese`/`only japanese` |

**★ 这里有一条直接影响我的设计、我必须诚实处理的发现：它的模型分组键是「语言」，不是体积/速度。**
我在初稿的 §7 里写过"若它按语言分组，§4.1 的依据需要重新论证"。现在需要兑现这句话：

**重新论证的结论：语言作为分组键对它成立，对我们不成立 —— 因为两边目录的语言分布完全不同。**

| | memo.ac | 我们 |
|---|---|---|
| 模型主体 | sherpa 一族 **27 条**，真实跨 `zh/en/ja/ko/yue/multi` **6 种以上** | whisper 一族 **12 组**：`multi` **8 组** + `en-only` **4 组** |
| 专用语言模型 | 多语言各有专用模型 | 只有 `zh` 2 条（Paraformer / sherpa 流式） |
| 按语言分组的结果 | 6 个大小相近的桶 —— **有效** | 多语种 8 / 仅英文 4 / 中文 2 —— **一个大桶 + 两个零头，且 `multi` 本身覆盖所有语言** |

→ **语言在我们这里分不开东西**（8/12 组都是 `multi`，落进每一个语言格子）。
这也正是 §4.1.3 的 **R-M2** 的由来：按 `languages` 排他筛选会把 8 个多语种模型从中文用户眼前抹掉。
**所以 `speedClass` 作为分组键的判断不变**，但我采纳它的两点：

- ✅ **采纳「语言下拉默认 `multi` 而不是 `all`」的思路** —— 我们的对应物是 ADR-011 的
  `notRecommendedForLanguage` 默认过滤（已实现），语义相同：**默认给一个已经筛过的视野，而不是全量**。
- ✅ **采纳「折叠组」而不是"平铺 + 筛选器"** —— 它的本地/在线插件是 collapsible，
  与我 §4.2 的「本地模型」折叠组、§4.1.2 的 `superseded` 折叠同构。

**不采纳它的 L1「引擎选择器」**：它有 8 条引擎路径才需要先选引擎；
我们 ADR-016 之后是 whisper.cpp / sherpa-onnx 两条、且 sherpa 侧只有 2 个模型 ——
先让用户选引擎等于多问一个他答不上来的问题（"我该用 sherpa 还是 whisper？"）。
我们直接按**用途**给推荐（§4.1），把引擎降级成卡片上的一行元信息。

### 7.3 LLM 的本地/在线：它**完全没有分组** —— 这一条我们比它做得多

`[取证]` 所有服务商在**一个扁平列表**里，只有一个优先级排序数组：

```
["openai","claude","gemini","deepseek","ollama","lmstudio"]   ← 置顶 6 家，其余按默认序
```

**这与我们 `packages/shared/src/providers.ts:108-115` 的 `MAINSTREAM_PROVIDER_IDS` 逐字相同**
（`model-mgmt` 已如实标注来源）。**"本地"在它那里只靠服务商自己的描述文字暗示**
（"Ollama 本地模型" / "LM Studio 本地服务"），**没有任何分组、Tab 或筛选器**。

→ **这恰好把判断① 夹在了中间，而我的位置是有理由的**：

| | memo.ac | 用户的骨架 | **D-10（本文）** |
|---|---|---|---|
| 本地/在线 | **不分**（靠读说明文字） | 两个并列节点 | **两个分组，权重不等** |
| 代价 | 用户得读完文案才知道 Ollama 是本地的 | 暗示两条路同等正当，与 ADR-016 矛盾 | 分组给了可见性，折叠 + 排序给了取向 |

**我不抄它的"不分组"**：它能不分组，是因为它的本地是"再多一个服务商"；
我们的本地是"**探测**你已装的服务"，动作和失败模式都不同（§2.3），不标出来用户就会去填一个假 Key。

`[取证]` 它的服务商表单：**服务名称 → Base URL → API 密钥（可选）→ 模型列表 + 「动态模型」开关**
（开了就去 `Base URL + /models` 自动拉）。
→ 与我们的 R-P2 同一个问题的两种答法：它按"是不是 OpenAI 兼容自定义服务"给开关，
我们按 `canRefreshModelList()`（`modelListSource.type`）给。**我们的更细也更诚实**
（它那 20 家人工转录的清单，在它那里也是没法刷新的，只是没说）。

### 7.4 「按用途分别配置」：★ 我们比它好，别改回去

`[取证]` **memo.ac 没有集中的用途矩阵。** 每个功能各自内嵌一个「选择服务/选择模型」，
背后是**各自独立的 IPC 端点**：`get-supported-summarize-services`、`get-supported-mindmap-services`、
`get-translate-providers`、`llm:get-services`。**翻译设置甚至有一份自己的服务商清单**
（还混着 Baidu/Google/DeepL/腾讯/阿里/小牛 这些老式 MT 插件）。

→ **这正是用户这次抱怨的那种分散的极端形态**：四个功能、四份清单、四个入口。
我们的 `LLM_PURPOSES = ['chat','summarize','translate']` + `llm.purposes` 单键 + INV-1 子集约束，
**在结构上优于它**。§4.2 把这一块与服务商清单并排放，就是把这个优势钉死。
（另：它把 summarize 与 mindmap 拆成两个端点；我们合成一档 —— `packages/shared/src/llm.ts:21-24`
的理由"两者都是读全文吐结构"仍然成立，且少一栏没人知道怎么填的东西。）

### 7.7 它有而**值得记一笔、但本轮不做**的一样

`[取证]` **「转写预设」**（`transcription.transcription presets`）：内置预设 vs 自定义预设，
