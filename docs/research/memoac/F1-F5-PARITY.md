| **量化选择**  | ❌ **没有，whisper 全 f16**                              | ✅ f16/q8_0/q5_0/q5_1 四档，且**真的改变下载的 variant**                                                                                           |
| 显存 fit 预检 | ❌ 无                                                    | ✅ `fitness.tier`                                                                                                                                  |
| 🔴            | —                                                        | **「跑基准」按钮打永久 501**（`models.ts:282`），且该页**不渲染 `benchmark.error`** → 点了毫无反应。**08-08 复核：未修，且已被用户真机撞到（G2）** |

**结论：要求 2.2 我们更强（量化 + fit 预检是它没有的）。**

## 2.5 第三层判据：用户能不能真的走到（2026-08-08 新增）

前两层比的是"做没做、做得像不像"。**这一层比的是"新用户从零开始，能不能真的用上"。**
加上它之后，上面几行的结论要改写 —— 而且改写的方向和前两层相反。

### 结构性差异：**它把引擎装在盒子里，我们发的是一个安装器**

`[实测]` memo.ac 的 Windows 包里，`resources/addon/whisper/bin/1.8.6/` **直接躺着**
`whisper-cli.exe` + `whisper.dll` + `ggml*.dll`（CPU 版），`bin/gpu/` 躺着 DirectCompute 版，
`cublas/whisper-cuda-bin-x64.7z` 躺着 CUDA 版。**装完 app，转写引擎已经在机器上了。**

`[实测]` 我们的 v0.3.0 包（41–59 MB）**刻意不含 whisper.cpp**
（`scripts/build-bundle.mjs:10`「不打包 ffmpeg / yt-dlp / whisper.cpp / 模型」），
只带探针与它跑得起来所必需的最小 ggml。**转写引擎要用户在网页上先装一个后端包。**

于是新用户到第一次转写的路径长度不同：

|                  | memo.ac          | OpenMemo                      |
| ---------------- | ---------------- | ----------------------------- |
| 装 app           | 1 步             | 1 步                          |
| 装引擎           | **0 步（随包）** | **1 步（下后端包，6–28 MB）** |
| 装模型           | 1 步（下模型）   | 1 步（下模型）                |
| **能失败的环节** | 1 个             | **2 个**                      |

**这不是"我们做错了"** —— 后端包分发正是要求 2.1 的题面，也是我们能覆盖
Linux/Vulkan/多量化的原因。**但它意味着我们多一个必经的失败点，而 08-08 三条真机故障里有两条正落在这里。**

### 三条真机故障对本表的影响

| 真机故障（用户 2026-08-08 报）                  | 打掉的是哪一行                                                    | 状态                                                                                                                        |
| ----------------------------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **探针不在最小包里 → 第一屏六个后端全报不可用** | **要求 2.1 全六步**（第一步就到不了）；连带 F1/F2/F3 全部无法转写 | `[报告]` 修复已进 `build-bundle.mjs`（缺探针即 `die`），**产品运行时行为非我所验**                                          |
| **空数据目录下装不了任何组件**                  | 同上 —— 新用户 100% 命中                                          | `[报告]` `e2e-coldstart` 最新 run 31262257036 绿，**但该路自己在 `f5a93dd` 里申报过"被打断会假绿"**，Manager 称三路尚无结论 |
| **点「安装模型」/「测速」完全没反应**           | 要求 2.2 的"浏览→下载"入口；以及我 08-07 就标过的 gap 5           | 「安装模型」✅ **已修**（`AsrModelPicker.tsx:134`，根因是 navigate 到当前页）；**「测速」未修**                             |

### 加上第三层之后，对齐表怎么改

- **要求 2.1**：前两层我们**远强**（它根本没有"检测→推荐"，只有三个按钮 + 一个显示
  `nvidia-smi` 原始输出的弹窗）。**第三层我们一度是 0** —— 六个后端全不可用时，
  一个更聪明的流程不如一个总能用的默认值。
  **memo.ac 的"笨"在这里是韧性**：默认 CPU、引擎随包，**没有任何一步可以失败**。
  → 改判：**设计我们赢，健壮性它赢；两层合起来目前打平，且我们的方差大得多。**
- **F1 / F2 / F3**：功能与实现等价或更强的结论不变，但**全部以"后端包装成功"为前提**。
  前提不成立时，这三行对新用户都是 0。**本表此前默认这个前提成立，这是它最大的盲点。**
- **F4 / F5**：不依赖后端包（导图走云 LLM，笔记管理纯本地），**第三层不影响**，结论维持。

**一句话**：**我们赢在能力上限，它赢在下限。而用户第一次打开看到的是下限。**

## 4. 差距清单（2026-08-08 重排：按**用户可感知的后果**排，不按工作量）

> 08-07 首版按"性价比（后果 ÷ 代价）"排。**本次改成按后果排** —— 代价仍然给出，但不再参与排序。
> **已闭的 gap 1/2/3/4/7 已从本列表移除**（见文首复核表）。
> **已被用户裁掉、不再列入**：TTS、移动端 App、协作、云账号、支付、cookie 下会员内容、
> macOS Intel、linux-arm64、ROCm、**多工作区（用户 2026-08-08 亲自裁定不做）**；
> 「LLM 接在线 API」是用户明确决定，不是差距。

### 🥇 G1 — 新用户到第一次转写之间有两个必经的下载，而它们刚刚全线塌过

- **后果（最重）**：F1/F2/F3 三条主线**全部**以"后端包装成功"为前提。前提一破，
  产品对新用户就是**完全不可用** —— 而 08-08 真机上它确实破了（六个后端全报不可用、
  空数据目录装不了任何组件）。memo.ac 在同样情境下**不会失败**，因为它把引擎装在盒子里。
- **代价**：三路正在修（探针进包 / 冷启动 / 真浏览器），**修复本身不需要我再投入**。
  真正要决定的是**结构问题**：要不要给最常见的那一档（CPU 基线包 6 MB / macOS 1 MB）
  **随包出厂**，把"能失败的环节"从 2 个降回 1 个。
- **建议：需用户拍板。** 技术上可行且很小（CPU 包只有 1–6 MB，不含 GPL 组件、许可证干净，
  与 ffmpeg/yt-dlp 不打包的理由**不同**）。但这动的是 ADR 级分发策略，**我不替你选**。
  ⚠️ 我的倾向：**做**。理由是本轮的教训正是"下限决定第一印象"。

### 🥈 G2 — 「测速」按钮点了静默失败（我 08-07 标过，没修，然后用户撞上了）

- **后果**：`ModelDetailPage.tsx:187` `void benchmark.mutateAsync(...)` → `models.ts:282` 永久 501，
  而该页**不渲染 `benchmark.error`** → 点了没有任何反馈。与"按钮是死的"在用户处完全一样。
- **代价：极低。** 要么隐藏/禁用并注明"未实现"，要么把 501 的 message 渲染出来。
- **建议：做（立刻）。** 这是本表里唯一一条"我上一轮就点名、代价极低、却因为没人做而变成真机故障"的条目。
  ⚠️ **判据不是"要不要做 benchmark"，是"不许静默失败"** —— 真做 benchmark 可以另议。

### 🥉 G3 — 删除现在不可逆，而且用户看不出东西还在

- **后果**：软删已正确 404（好事），但**全 daemon 零 restore 路径**。
  用户删错一条笔记 = 永久失去（数据其实还在库里，只是没有任何入口）。
  这一条**因为 404 修好了而变重**：以前还能靠 URL 撞回去，现在不能了。
- **代价：低。** 一个 `?deleted=1` 列表 + 一个把 `deleted_at` 置 NULL 的端点。
- **建议：做。**

### 4. G4 — 设置项分散且大部分没有 UI

- **后果**：竞品 12 个设置页签；我们设置分散在 `/settings`、`/models`、`/runtime`，
  且约 15 个后端 settings 键（`asr.defaultEngineId`、`asr.language`、`download.concurrency`、
  `runtime.selectedBackend` 等）**没有任何 UI**。用户找不到、也改不了。
- **代价：中。** 纯前端信息架构 + 若干表单。
- **建议：做，但排在 G1–G3 之后。**

### 5. G5 — 文件夹改不了名，笔记移不进文件夹

- **后果**：建错名字只能删了重建；笔记无法归档到文件夹 —— F5「笔记管理」的组织能力实际残缺。
  `useRenameFolderMutation` / `useMoveNoteMutation` **两条都写好了、都零调用者**
  （`NoteActionsMenu` 只接了 delete/rename）。
- **代价：低。** 接线即可，端点与 hook 都在。
- **建议：做（可与 G3 合并一轮）。**

### 6. G6 — Linux CUDA 仍无包，对外口径仍未改

- **后果**：Linux + N 卡用户只能走 Vulkan 或 CPU。**这条本身可接受**（Vulkan 覆盖得到），
  但文档若仍宣称支持 Linux CUDA 就是不实。
- **代价**：真做高（`libcudart` 随包分发未解）；改口径极低。
- **建议：不做（维持现状），只改口径。** 这条 R-06 提过、08-07 我又提过，仍未做 —— 属 §13 那类"裁完没回去改原文"。

### 不建议做（"它有我们没有" ≠ "我们该有"）

| memo.ac 有                                              | 为什么不建议                                                                     |
| ------------------------------------------------------- | -------------------------------------------------------------------------------- |
| OCR（RapidOcrOnnx + PaddleOCR）                         | 章程 F1–F5 无此项；引入两个原生二进制 + 三个 ONNX 模型，维护面大幅扩张           |
| 插件市场（`integrations.memo.ac/plugins/v2`）           | 需要长期运营的服务端；且它的 `vm2` 沙箱**已废弃且有逃逸漏洞**（沿用当年判断）    |
| 模型清单**运行时**从 `models.memo.ac/all-models` 热更新 | 章程是 local-first，不宜新增出网依赖；清单进 git 更可审计                        |
| PDF 导出                                                | **它自己也没有** —— 菜单项 `disabled:!0`，无 PDF 引擎。别照抄一个死功能          |
| 云 ASR 插件 4 家                                        | 章程未要求；且与「本地优先」张力大                                               |
| **GPU 加速做成付费墙**                                  | 它把 GPU 加速做成试用额度制（`useProLimit()`）。我们没有商业模式要养，**不要抄** |

**新发现的「明确不要照抄」**（补充当年那两条 `vm2` / `whisper-server --host 0.0.0.0`）：

1. **静态密钥 AES 安全剧场**：它用**硬编码密钥+IV** 的 AES-256-CBC 只加密 Notion secret，
   24 家 LLM 的 `apiKey` 全明文躺在 `conf/setting.conf` 旁边，全 bundle `safeStorage` 0 命中 `[报告 R-06]`。
   **加密假象比明文更危险**；我们的做法（明文但 ADR-006 强制向用户 disclosure）更诚实。
2. **`session.resolveProxy("https://www.google.com")` 探测系统代理** `[报告 R-06]`：
   探测目标对其主要受众（被墙用户）本身不可达。
3. **默认 CPU + 无硬件检测**：它把"选哪个后端"整个甩给用户。我们已经比它好，别退回去。
