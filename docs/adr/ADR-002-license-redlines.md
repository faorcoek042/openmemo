## 决策 1：许可证政策 = 个人自用档

因不对外分发，GPL 的分发义务基本不触发（GPL 约束的是**分发**行为，不是自用）。因此：

| 原 v1 红线 | v2 裁决 | 说明 |
|---|---|---|
| `ffmpeg-static` (GPL-3.0) | ✅ **允许使用** | 省掉自建 FFmpeg 的 CI 工作量，macOS 无 LGPL 预编译源的难题直接消失 |
| yt-dlp 官方二进制 (GPLv3+) | ✅ **直接内置** | 用户明确决定 |
| ~~`@blocknote/xl-*` (GPL-3.0)~~ | ~~✅ 允许~~ → ❌ **撤销（2026-08-08）** | 见下方「§撤销记录」 |
| `tldraw`（专有，生产需付费） | ❌ **仍禁止** | 专有许可证与"自用"无关，仍需付费 |
| `@tiptap-pro/*`（付费专有） | ❌ **仍禁止** | 同上 |
| `ten-vad`（非竞争条款） | ⚠️ 允许但不推荐 | `silero-vad` (MIT) 各方面更好，无理由用它 |
| FFmpeg `--enable-nonfree` | ⚠️ 自用可，**绝不分发** | 若日后改变分发意图，此项是硬阻断 |
| Moonshine 非英语模型（非商用） | ✅ 允许 | 自用属非商用 |
| Meilisearch (BUSL-1.1) | ✅ 允许 | 但选型上仍推荐 SQLite FTS5 方案（更轻、无服务进程） |

**保留的工程约束**（与许可证无关，纯质量要求）：
- CI 仍跑 `license-checker`，但**降级为报告模式**（生成清单，不 fail build）。
- 所有第三方组件的许可证记入 `vendor/manifests/*.json`，保持可追溯。

> **升级路径**：若日后要商用，需回滚到 v1 红线——主要工作是自建 LGPL FFmpeg（见 R-03 §4）
> 和把 yt-dlp 改为可选插件（R-03 §5.5）。这两处应保持**架构上可替换**（走适配层），
> 使回滚成本可控。这是硬性设计要求，写入 D-01。

### 撤销记录：`@blocknote/xl-*` 那一行（2026-08-08，Manager 授权 `prebuilt` 就地改）

**何时**：2026-08-08。**谁**：agent `prebuilt`，经 Manager 当轮明确授权
（`docs/adr/**` 归 Manager，此处按 ADR-003 §7.6 的先例就地改并留痕）。

**依据**：调研预编译包时对"我们到底要分发哪些字节"做了逐包核实，发现这一行
**是一张空头许可 —— 它批准的那个包从来没有被采用过**：

| 检查 | 结果 |
|---|---|
| `grep -rn "blocknote" --include=package.json`（排除 node_modules） | **0 命中** |
| `grep -rni "blocknote"` 遍历 `apps/` + `packages/` 的 ts/tsx/js/json | **0 命中** |
| `ls node_modules/.pnpm/ \| grep -i blocknote` | **0 命中（根本没装）** |
| `grep "blocknote" pnpm-lock.yaml` | **0 命中** |

实际采用的富文本编辑器是 **TipTap**（`@tiptap/*` 3.29.2，全部 MIT，逐个读已安装的
`package.json` 的 `license` 字段核实过）。这一行是 v1 从 R-03 的**候选清单**里
誊过来的，它批准了一个候选，而那个候选后来落选了。

**为什么必须删而不是留着**：v2 放宽的前提是「不对外分发」。
**2026-08-08 用户裁决要把预编译包发到公开 Release —— 前提没了。**
在这个新前提下，这一行的含义变成了「可以往一个要公开分发的产物里引入 GPL-3.0 的编辑器」，
而那会**当场触发本 ADR 自己写的那条硬阻断**。

留着它的风险不是理论上的：一个未来的人有正当理由把它读成「ADR 已经批过了」——
**而全仓唯一说"不行"的地方，恰恰是同一份文件的另一行。**
一条需要读者自己发现前提已经变了的许可，等价于一条迟早会被误用的许可
（PROTOCOL §7 补充那条判据的同构：**判据不是"要记得前提变了"，是"读错了也不会造成后果"**）。

**现状**：本预编译包的生产依赖闭包**零 GPL/AGPL/LGPL**（268 个包全量核实，
见 `docs/design/D-17-prebuilt-bundles.md` §1.1）。ffmpeg 与 yt-dlp 仍是
GPL-3.0-or-later，仍**不随包分发**，由用户机器直连上游取 —— 那条边界没有变。

## 决策 2：shadcn/ui 的 C2 豁免（唯一豁免项）

shadcn/ui 的分发模式**就是**源码复制进项目（MIT，设计意图如此，无上游包可依赖）。
**批准豁免**，条件：
- 隔离在 `src/components/ui/` 单一目录，不与业务代码混放。
- 目录内 `SOURCE.md` 记录来源 URL + 复制时的版本 + 许可证（维持 C2 本意：可追溯）。

## 决策 3：思维导图库 —— 裁决 R-01 与 R-03 的分歧

| 来源 | 主张 |
|---|---|
| R-03 (`oss-scout`) | `mind-elixir` (MIT)，编辑优先，内置撤销/拖拽/右键 |
| R-01 (`memo-researcher`) | `markmap`——因为 **memo.ac 实际用的就是它**（已取证） |

> **事实订正（`architect` 2026-08-02 核实上游）**：npm 包名是 **`mind-elixir` v5.14.0**，
> **不是 `mind-elixir-core`**（后者在 npm 上 404）。且 `MindElixirData` 无 `linkData` 字段。
> 本 ADR v1/v2 初稿的包名有误，此处订正；决策实质不变。

**裁决：`mind-elixir` 为主编辑器，`markmap` 为可选只读视图。**

理由：用户需求原文是"**整理**思维导图"，整理 = 编辑，是主路径。markmap 是
"Markdown → 导图"的单向渲染器，编辑能力弱——这正是 memo.ac 的局限，
且 `memo-researcher` 实测发现它还有导出模糊问题。我们没有理由继承竞品的短板。

**硬性设计要求**：思维导图数据模型必须**库无关**（自有 schema + 适配层），
两个渲染器都是这个 schema 的消费者。切换成本必须可控。写入 D-01。
