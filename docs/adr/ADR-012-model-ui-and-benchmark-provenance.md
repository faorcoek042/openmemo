## 真实链路验证（要求 2.2 已闭环）

真下 `ggml-base-q5_1`（59,707,625 B）：

```
POST /api/models/pull → 202 jobId=01KZ0KDT98V0JJS7CP53T94K17
再点一次 → deduplicated=true sameJob=true
SSE: job.created → sources.probed → job.progress(19/39/59/79/99%) → model.activated
     → model.installed → storage.changed → job.state(succeeded)
installed: integrity=ok sha256=422f1ae452ade6f3…  |  catalog: installed=true
DELETE 使用中的模型 → 409 MODEL_IN_USE + remediation
```

门禁 exit code 全 0；Zip-Slip 38/38；`verify-offline` 25/25；三份 manifest zod VALID。

## 决策 1：**`ReferenceBenchmark` 与 `benchmark` 分离 —— 批准，并细化 ADR-004 决策 3**

`model-mgmt` 遇到一个我的规则没覆盖的情况：`gpu-runtime` 实测的中文数字
（large-v3-turbo 2.7x 实时）是**有出处的真实测量**，但不是**用户本机**的测量。
他没有硬塞进 `benchmark`（语义是本机实测），而是**新建 `ReferenceBenchmark`**，
强制带出处（机器/后端/音频/时长/语言/置信度），UI 严格区分
「本机实测」vs「参考机实测，仅供参考」，且只在后端匹配时采用。

**批准，并据此细化 ADR-004 决策 3 的表述**：

> 禁止的是**编造**数字，不是禁止**有出处的测量**。
> 任何展示给用户的性能/质量数字必须能回答三个问题：**谁测的、在什么机器上测的、什么条件下测的**。
> 答不出任一项 → 不许显示。

他顺手删掉了 R-04 §9.2 原稿里的 `★★★★☆` 质量星级 —— 同样是无出处的数字。**正确。**

## 决策 2：**"本机无浏览器就不声称点通了" —— 表彰**

本机 chromium / firefox / playwright 均无，他**没有假装点过 DOM**，
改为验证构建产物被正常托管（`/models` 200）+ 组件文案确实在 shipped bundle 里（8/8 命中）。

这是本项目诚实规则的正确应用。**但验证缺口是真实的** → 见决策 5。

## 决策 3：`reference-server.mjs` 转给 `oss-scout` 照抄进 `apps/daemon` —— 批准

`apps/daemon` 目前**一个业务 endpoint 都没有**，`model-mgmt` 为了真跑链路
在自己领地写了 `reference-server.mjs`（同一份 shared 契约 + 真实下载器 + 真实 manifests + 真实 fitness）。

**这不是重复劳动，是把接口跑通了再交接。** 指派 `oss-scout` 照抄进 `apps/daemon`，**别另起炉灶**。

## 决策 4：ADR-011 的三条已落地，验收通过

1. `lang=zh` → base/small/tiny/medium 默认隐藏 + 说明「会把维基百科听成危机摆科」+ **可一键解除**；
   `lang=en` → base 恢复 `recommended`。**改的是默认值不是能力**，符合裁决。
2. **Zip-Slip 38/38 带真实攻击用例**：`../evil.txt`、POSIX/Windows/UNC 绝对路径、tar 真实 symlink、
   条目数/字节数上限、**谎报体积的 zip bomb**。攻击后 destDir 外零文件、symlink 从未创建。
   诚实限制：不支持 ZIP64，**检测到即报错不静默**。
3. `FitResult` 加 `speedTier`/`speedSource`，large-v3-turbo 标 **23 分钟/小时**并入 `reasonZh`
   → **"装得下"不再被读成"体验好"**。这正是我要的。

## 决策 5：浏览器 E2E —— **不进待环境清单，先尝试自己装**

`model-mgmt` 建议把"无浏览器"列入待用户提供环境。**我不同意就这样上报**：
本机是 Linux + 有网 + 磁盘 16 GB 可用，`playwright install chromium` 有很大机会直接成功。
**在向用户要资源之前，先自己试一次。** 指派 `model-mgmt` 尝试；装不上再进清单，并附真实报错。

理由：要求 2.1 / 2.2 的核心是"用户在网页上点几下"，而**至今没有任何一次真实的点击被验证过**。
这是当前最大的验证缺口，值得花一轮去关。

## 决策 6：Ed25519 验签已实现但生产未启用（无密钥），**供签名却无密钥时失败关闭绝不放行** —— 批准

"没有密钥就拒绝，而不是跳过验签"是正确的失败方向。

> ⛔ **本决策的措辞「未启用（无密钥）」于 2026-08-07（T-171）被用户推翻。**
> ~~"未启用"暗示"等密钥到位就会启用"~~ —— 这个前提不成立：**根本没有远端目录要验**，
> 而会取远端目录的那条管线已被裁决删除。**订正与实际执行范围见文末 §附-B。**
> "失败关闭绝不放行"这半**仍然成立且未被推翻**，函数行为一个字没改。
> 本决策原文不许删，留作可追溯。
>
> ⚠️ **2026-08-10 追加**：§附-B 说"验签函数今天不在任何生产路径上"——这句话
> 现在**不再成立**了，见文末 §附-C：验签函数第一次有了生产调用方（D-20 §17
> "检测更新"）。**"v1 不做远端目录"这半没有变**：新增的是只读的"查有没有更新"，
> 不是把 §附-B 说的那条被删的远端加载管线接回来。

## 决策 7：i18n 统一 —— 排在 `architect` 的 locales 落地之后

`model-mgmt` 的两个 feature 目前用内联中文。不返工，等 T-021 的 i18n 基础设施就位后统一抽取。

# 附-B：决策 6 的措辞订正（2026-08-07，T-171）

**何时 / 被谁 / 依据什么**：2026-08-07，**用户本人**在 T-171 任务书里裁定
（"上一位倾向删但没删……**现在我裁：删**"），并**明确授权 agent 就地改 ADR**
（"原文用删除线保留，不许删原文"）。做法照抄 ADR-003 §7.6 的先例。
**完整论证、逐符号删除清单与实测证据写在 `ADR-010 §附-A`，本节只记与决策 6 直接相关的部分，
不重复。**

## 被推翻的是哪个字

原文说验签"**已实现但生产未启用（无密钥）**"。这句话在字面上是真的，
但它**暗示了一个不存在的未来**：读者会理解成"等密钥配发就能启用"。

`[T-171 实测]` 真实情况是：

| 以为                       | 实际                                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------- |
| 差一把密钥                 | 差的是**整条远端目录管线**                                                                              |
| 目录来自远端，只是还没验签 | 目录是 `vendor/manifests/*.json`，**git 跟踪、随仓发布**，daemon 走 `fs.readdir` 本地读盘，**从不联网** |
| 接上密钥即可启用           | 全仓**无 `.sig`、目录 JSON 无 `signature` 字段、无任何脚本会签目录**                                    |

用户的判词（抄录）：**"留着它的最大风险不是它有 bug，是下一个人会以为目录是被验签的"** ——
而今天目录的实际保障是**编译期 host 白名单 + 强制 sha256**，完全是另外两件东西。

**所以决策 6 的正确读法改成**：

> v1 **不做远端目录**，因而**没有目录需要验签**。取远端目录的分层加载器已删
> （`ADR-010 §附-A`）。验签函数本身保留，但它今天**不在任何生产路径上**，
> 且**不存在"配发密钥就会启用"这条路径** —— 将来真要做远端目录，
> 按那时候的约束重新设计。

## 没有被推翻的部分（别连坐）

- **"供签名却无密钥时失败关闭绝不放行"** —— 仍然正确，**行为一个字没改**。
  `verifyCatalogSignature` 在 `publicKey == null` 时仍然 `throw`，不返 `true`、不跳过。
- **函数本身保留**，因为 `packages/downloader/scripts/verify-unpack.mjs` 是它的**真实调用方**
  （13 条断言，含拿真 Ed25519 密钥对验真签名；对照组实测 `53 passed, 0 failed`）。
  用户在任务书里立了"**拒绝删任何有真实调用方的东西**"的硬约束，这条在此触发。
  → **删除只执行了远端加载器那族，验签函数未删。** 详见 `ADR-010 §附-A`。

## 给下一个人的判据

**"已实现"不等于"接近可用"。** 这条 ADR 当年批准的是一个函数的**失败方向**，
而不是一条**特性的完成度** —— 两者被同一句话捆在一起写了半个月，读的人自然会合并理解。
下次写"已实现但未启用"时，请把**未启用的原因**写成可核验的清单
（缺密钥？缺调用方？缺被验的对象？），否则它会被读成"就差最后一步"。

# 附-C：§附-B「今天不在任何生产路径上」被取代（2026-08-10）

**何时**：2026-08-10，D-20 §17（"检测更新"实现）。
**被谁**：本次任务在任务书里明确要求补写这一节，承接的是 §附-B 那句
"验签函数本身保留，但它今天不在任何生产路径上，且不存在'配发密钥就会启用'这条路径"——
这句话本身现在过时了，需要一条订正而不是删除。
**完整论证与实测证据写在 `ADR-010 §附-B`，本节只记与决策 6 直接相关的部分，不重复。**

## 被取代的是哪句

§附-B 的判据表格里那一行**"接上密钥即可启用 → 全仓无 `.sig`、无脚本会签目录"**，
在 2026-08-10 之前一直成立。现在：

- **仍然没有**任何脚本自动签目录，也**仍然没有**真实密钥被配发或提交进这个仓库——
  这两点没变，§附-B 关于"密钥"的判断依然准确。
- **变了的是"调用方"这一格**：`verifyCatalogSignature` 从"零生产调用方，只被
  `verify-unpack.mjs` 手动测试调用"变成了有一个真实生产路径 ——
  `apps/daemon/src/http/rest/updates.ts` 的 `GET /api/updates/check`
  （经 `catalogUpdate.ts` 的 `checkForUpdates()` 编排）。

## 没有被取代的部分（别连坐）

- **"v1 不做远端目录"没有变**：新写的是"查一下有没有新版本"，只读、不下载、
  不安装、不改任何本地状态（D-20 §11.3 的硬约束）。§附-B 说的那条被裁决删除的
  三层远端加载器（`loadManifest`/`loadModelManifest`/`loadBackendManifest`，
  `ADR-010 §附-A`）**没有复活**，git 历史里躺着。
- **"失败关闭绝不放行"这半继续成立**：`verifyCatalogSignature` 在无密钥时仍然
  `throw`；新增的 `verifyCatalogSignatureSafe()` 方向相同（无密钥/验不过 = 拒绝），
  只是把"抛异常"换成"返回 `false`"这一种更适合编排代码的形状，不是放宽判定。
- **生产环境今天依然验不到任何东西**：`OPENMEMO_CATALOG_UPDATE_URL` 未设，
  端点诚实回 `source: "not-configured"` —— "有生产调用方"不等于"生产在验签"，
  两者是两件事，别混。

## 给下一个人的判据（延续上一条）

"没有生产调用方"这句话的保质期取决于**下一次谁往这条链路上接东西**，不是永久事实。
本节示范的订正方式：不删 §附-B 的表格（那些行在 2026-08-10 之前都是准确的历史记录），
只标注"哪一格现在不同了"，理由与实测证据另起一节。**完整实现细节、三条前提各自的
代码落点、CI 覆盖范围，见 `docs/design/D-20-bundled-deps.md` §17。**
