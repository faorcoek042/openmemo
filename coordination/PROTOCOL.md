# Agent 协作协议 v1

所有 agent **必须**遵守。Meta Manager 是唯一的调度者与合并者。

## 0. 角色

- **Meta Manager**（主会话）：分派任务、读摘要、做决策、写 ADR、合并成果。不写业务代码。
- **Lead Agent**（opus5）：领域负责人，可再派 sub-subagent（琐碎活用 sonnet5）。
- **Worker Agent**（sonnet5）：执行明确定义的机械任务。

## 1. 通讯机制 = 共享文件系统（单一事实来源）

```
/root/memo/
├── docs/
│   ├── 00-CHARTER.md          # 项目章程（Manager 所有，只读）
│   ├── research/              # 研究报告  R-*.md
│   ├── design/                # 设计文档  D-*.md
│   └── adr/                   # 架构决策记录 ADR-NNN-*.md（仅 Manager 写）
├── coordination/
│   ├── PROTOCOL.md            # 本文件
│   ├── BOARD.md               # 任务看板（仅 Manager 写）
│   ├── ROSTER.md              # Agent 花名册（仅 Manager 写）
│   ├── inbox/<agent>.md       # Agent → Manager 的回执（Agent 写，追加）
│   └── tasks/T-NNN.md         # 任务卡（Manager 写规格，Agent 写进展）
```

### 规则

1. **写自己的文件，读别人的文件。** 除 `inbox/<自己>.md`、自己被分配的 `tasks/T-NNN.md`
   和自己交付的 `docs/**` 文件外，不得修改任何文件。避免写冲突。
2. **跨 agent 依赖靠文件，不靠猜。** 需要别人的产出时，读对方的 `docs/` 交付物。
   若尚不存在，在自己的 inbox 里写 `BLOCKED: 等待 <文件路径>`，然后先做不依赖它的部分。
3. **绝不修改他人的交付物。** 有异议 → 在自己 inbox 里写 `DISPUTE:` 条目，Manager 裁决。

## 2. 交付物格式（强制）

每份 `docs/**` 文档**必须**以这个块开头，Manager 只读这一块：

```markdown
---
id: R-01
author: <agent-name>
status: draft | ready | superseded
date: YYYY-MM-DD
---

## TL;DR（≤ 25 行，Manager 只读这里）

- 结论 1
- 结论 2
- 关键取舍：...
- 未验证/存疑：... <-- 必填，没有就写"无"
- 对其他 agent 的影响：...

## 详细内容

（正文随意长）
```

## 3. 回执格式（`coordination/inbox/<agent>.md`，追加不覆盖）

```markdown
## [YYYY-MM-DD HH:MM] <TASK-ID> <STATUS>

STATUS ∈ DONE | PROGRESS | BLOCKED | DISPUTE | QUESTION
交付: <文件路径列表>
要点: <≤5 行>
下一步建议: <≤3 行>
需要 Manager 决策: <有则列出，无则写"无">
```

## 4. 诚实规则（不可协商）

- 没验证过的写 **"未验证"**。没跑通的写 **"未跑通"** 并附错误输出。
- 不允许编造 API、版本号、benchmark 数字。不确定就去查，查不到就标 `UNKNOWN`。
- 网络受限导致无法验证的，明确写 `无法联网验证`。

## 5. 派生 subagent 的规则

- Lead 可派 sub-subagent，但**自己名下同时运行的不得超过 2 个**（全局上限 4 由 Manager 控制）。
- 机械性工作（改文件名、批量重写、跑格式化、写样板代码）→ 用 sonnet5。
- 需要判断/设计/取舍的 → opus5。
- 派出去的 agent 完成后不要 kill，记录其 name/id 到自己的 inbox 以便复用。

## 6. 上下文节约

- 不要把大文件全文贴进回复。写到磁盘，回复里只给路径 + TL;DR。
- 读别人的文档时优先只读 TL;DR 块。

## 7. 共享产物：`apps/web/dist` 不许被验证构建覆盖

`:10000` 的演示实例（用户唯一能从 NAT 外访问的入口）**直接托管 `apps/web/dist`**。
任何 agent 跑一次 `vite build`，都会**换掉用户正在看的前端** —— 进程没重启、
版本号没变、页面却已经是别人的半成品了。没有任何东西会报错。

所以：

- **验证构建一律 `--outDir` 到 `/tmp/<你的名字>/`**，例如
  `vite build --outDir /tmp/llm-picker/dist`。
- `apps/web/dist` **只由 Manager 在重启前统一构建**。
- 不确定某条命令会不会写进去，就先 `--outDir` 到 `/tmp`。

同理适用于 `:10000` 本身：**只读，不重启、不 kill、不占用该端口**。要起服务用别的端口。

（此规则源于 `llm-picker` 的主动申报 —— 它构建完才意识到，并如实报了出来。
规则针对的是"没人知道这条线存在"，不是针对它。）

## 8. 断言 DOM 节点不许直接比对象 —— 会 OOM，而且假装成"测试挂了"

`assert.equal(domNode, null)` **失败时**，node:test 要为两边算 diff，`util.inspect` 会顺着
`parentNode` / React fiber **展开整棵树**。实测进程涨到 **10.5 GB**，表现是：

- 不是"断言变红"，而是**整个测试文件炸掉**（57 秒后 `'test failed'`，同文件里其它 suite 一个没跑）
- **同进程里别人的用例统计一起被带偏**

**比"护栏没变红"更难查** —— 因为它看起来像环境问题、像超时、像别的 agent 把仓库弄坏了，
而不像"我这条断言写错了"。

所以：**断言 DOM 存在性一律先转成布尔或字符串再比**。

```js
assert.equal(el === null, true); // ✅
assert.equal(!!container.querySelector(sel), false); // ✅
assert.equal(el, null); // ✘ 失败时 OOM
```

同理适用于任何**可能持有父引用的对象**（DOM 节点、fiber、带 `parent` 指针的树节点、
含循环引用的图）。判据不是"它是不是 DOM"，是"**它失败时会被 inspect 展开多大**"。

（源于 `models-page-fix` 的反向验证 —— 它第一次没拿到红灯，追下去才发现是 OOM，
并如实报了出来而不是重跑一次糊弄过去。）

### §7 补充：用 `pnpm build:safe`，不要靠记性

§7 禁止验证构建覆盖 `apps/web/dist`，但**两名 agent 先后踩了同一个坑**，成因是同一个：
HANDOFF 教的启动步骤就是 `pnpm -r build`，而禁令针对的是它的**子步骤**（`vite build`）——
两句话隔了几十行，**读到禁令的人不会意识到自己刚敲的那条命令就违反了它**。

所以禁令改成脚本：

```bash
pnpm build:safe     # ✅ 构建除 web 之外的全部包，不会碰 apps/web/dist
pnpm -r build       # ⚠️ 含 vite build，只有 Manager 在重启前跑
```

**判据不是"要记得别跑那条命令"，是"跑错了也不会造成后果"。**
一条需要人时刻记住的规则，等价于一条迟早会被违反的规则 —— 这次是两次。

（源于 `ytdlp-install` 的自我申报：它违反后没有掩盖，而是分析出"两句话隔了 60 行"
这个真正的成因并建议加脚本。）

## 9. 数据目录指针是**全局单例**，测试搬迁绝不能碰它

指针文件在 `~/.local/share/openmemo/datadir.json`，**按设计就在数据目录之外**
（鸡生蛋：数据搬走后得先知道搬到哪了，指针跟着走就再也找不到了）。

代价是：**它是全机器共享的一份**。任何 agent 跑一次会写指针的搬迁流程，
就把**用户的 demo 一起搬走了** —— 而且不会立刻显形，要等下一次重启。

已经发生过一次：某轮测试把它改成了 `/tmp/<agent>/movedst`，
Manager 几小时后重启 demo，daemon 挂到一个空壳上 ——
**用户的 DeepSeek key、模型、转写记录全部"消失"**，自检从 `ok:20 fail:0` 掉到 `ok:7 fail:5`。
数据一个字节没丢，但从界面上完全看不出这一点。

所以：

- **测搬迁只调纯函数**，不走会写指针的那条路径；
- ~~非走不可就**先备份指针、跑完还原、并核对内容**~~ → **见 §9-bis：备份还原法已作废**；
- Manager 重启前**先确认 `dataDir` 是不是用户那个**。

**判据：一个进程级测试写了机器级状态，就已经越界了 —— 哪怕它自己的临时目录用得很干净。**

### §9-bis 那次事故有**第二条路径**，而它藏在最常跑的那条命令里

上面这条规则只说了"**测搬迁**别碰指针"。**它漏掉了 `pnpm -r test` 本身。**

`apps/daemon/src/storage/restart-datadir.test.ts` 要验的性质是
「指针指向别处时，普通重启的 dataDir 不能被带偏」——
它**必须**让 daemon 真读到一个指向别处的指针。它当时的做法**恰好就是上面那条被允许的兜底**：
备份 → 写诱饵 → `after()` 还原。还原写得对，内容也确实还原得回来。

问题是：**`after()` 只在正常结束时跑。**

进程被 `kill`、崩溃、超时、机器重启 —— 指针就**永久**停在 `/tmp/om-rd-decoy-*` 上。
而 `pnpm -r test` 是一天要跑十几次的命令。事故当时归因于"某个 agent 的搬迁测试"，
**这条路径一直开着，谁都没看见**。

`[实测]` 把当时那段备份/还原逻辑逐行搬到假 HOME 下跑，中途 `kill -9`：

```
--- ① 正常跑完（after() 有机会跑）
{ "dataDir": "/root/data-memo", ... }          ← 还原成功
--- ② 跑到一半 kill -9（after() 没跑）
{"dataDir":"/tmp/om-rd-decoy-XXXX"}            ← 用户的 demo 已经废了
```

所以规则改成：

- **判据不是"还原得对不对"，是"被 kill 也不能留下坏状态"。**
  任何"写下去 → 再改回来"的方案都在结构上满足不了它 —— 写与还原之间必然有窗口。
- **正确的修法是让它根本不写那个全局位置。**
  指针位置已经可以被 `OPENMEMO_POINTER_FILE` 覆盖（与 `OPENMEMO_DATA_DIR` /
  `OPENMEMO_EXT_DIR` / `OPENMEMO_MODELS` 同一套约定）。测试在**模块顶层**设它，
  窗口为零；node:test 一个测试文件一个子进程，进程一退它就没了，**不需要清理代码**
  —— 而"清理代码"正是上面那个靠不住的东西。
- **覆盖要有人守。** 该测试里有一组用例专门断言
  「本次要写的指针路径必须在 tmpdir 里、且不在 `$HOME` 底下」+
  「`pointerFile()` 回读必须等于我们设的那个」。
  重定向被"顺手简化"掉时会当场红 —— 而不是等用户的 demo 挂了才知道。

**推广到一般情形（这条才是要记住的）：**

> 判断一个测试有没有越界，看的不是"它清理得干不干净"，
> 而是**"把它 `kill -9` 在最坏的那一行上，机器会留下什么"**。
> 留下任何机器级的坏状态 —— 就得改成"根本不写"，而不是"写完记得擦"。

同类需要用这条判据重新审一遍的（**尚未逐个核查**）：全局配置文件、
`~/.config` / `~/.cache` 下的任何路径、系统级临时文件的固定名字、端口占用、
以及任何 `process.env` 之外的进程间共享状态。

**推论：变异检查这类"故意把安全性质拿掉"的工具，必须假设变异体是敌对的。**
`scripts/mutation-check.mjs` 第一版就栽在这上面 —— 它有一条变异是
"让 `pointerFile()` 忽略覆盖、改回硬编码全局位置"，跑完**它自己把用户的指针写坏了**：
一个用来防止事故的工具，复现了那场事故。现在每个变异体都跑在假 `HOME` / `XDG_DATA_HOME` 里。

## 10. 反向验证不许在共享工作树里做

反向验证要求"把修复拆掉、确认真的变红"。问题是：**拆掉的那几分钟，`dist` 里装着故意坏掉的代码**，
而别的 agent 同时在跑 `pnpm -r test`。

已经发生：某轮六组反向验证期间，另一路 agent 撞上 25 条红，逐个排查后确认「不是我的」——
**而拆修复那一方每次都还原了、`grep` 残留一直是 0。**

> **「最终状态干净」救不了「过程中别人跑了一次」。**

判据与 §9-bis 是同一条的两面：

- §9-bis 问的是 **「在最坏的那一行 kill -9，机器上还剩下什么」**
- 这一条问的是 **「在最坏的那一秒，别人看到的是什么」**

所以：

- **反向验证跑在 `/tmp` 的隔离副本上**（`scripts/mutation-check.mjs` 已经是这个形状，照它做）；
- 非在共享树里不可时，**先在 inbox 申报时间窗**，并在完成后主动说一声；
- 撞上红灯的一方，**先看 inbox 有没有人正在做反向验证**，再判断是不是自己的。

**推论：一个"必填字段"类的改动，在补齐所有构造点之前，红是必然的，不是意外。**
这类改动要么一次提交到位，要么申报窗口。

（源于 `catalog-truth` 的主动认领与成因分析 —— 它没有说"最后是绿的"，
而是指出中间态被别人看见了。）

## 11. 残留进程会把「本该失败」变成「假通过」—— 而且是静默的

**本轮三个 agent 各撞了一次同一个形状**，所以它进协议：

- `bundle-launch`：一条诊断步骤把 daemon 起了起来并**泄漏**，占着 17650。
  于是「`open` 一个被 Gatekeeper 拒绝的 `.command`」这一步**报出界面可达 HTTP 200** ——
  而那个 200 是**泄漏进程**应答的，`open` 自己是 ETIMEDOUT。
  **差一点就据此报告「macOS 双击是好的」，而用户手里的包明明打不开。**
- `e2e-import`：健康检查连上了同端口的一个游离 daemon，**0.5 秒就报「就绪」**，
  而它自己拉起的那个已经死了。
- `e2e-record`：跳过的平台报告**「成功，零步骤」**。

**为什么它比测试失败危险得多**：失败会被查，**假通过不会**。
它还会**反向**污染结论 —— 你会去修一个不存在的问题，或者宣布一个坏掉的东西是好的。

与 §9-bis / §10 是同一族的第三面：

|         | 问的是                                                         |
| ------- | -------------------------------------------------------------- |
| §9-bis  | 在最坏的那一行 `kill -9`，**机器上还剩下什么？**               |
| §10     | 在最坏的那一秒，**别人看到的是什么？**                         |
| **§11** | 我这次测到的「通过」，**会不会根本不是我启动的那个东西给的？** |

所以：

- **任何「起服务再探测」的测试，探测前必须先证明那个端口是空的**，
  并在不空时**当场判失败**（而不是继续跑下去拿一个无意义的绿）。
- **收尾按 pid 收整棵进程树**（Windows 上 `child.kill()` 杀不掉 `cmd.exe` 底下的 `node.exe`；
  POSIX 上 `exec` 之后才是同一个 pid）。**仍然按 pid，不许 `pkill -f`** ——
  模式匹配会打到别人的进程，那是另一种越界。
- **一切外部命令带超时。** 没有超时的步骤既会拖死整条腿，
  又会在被杀时把孙子进程留下来 —— 上面两个后果它一个人全占。
- **「跳过」不许渲染成「成功」。** 零步骤的绿灯是本条最廉价的一种发作。

**判据**：一个绿灯，必须能追溯到**是我这次启动的那个东西**给的。**追溯不到，它就不是证据。**

> Manager 注（2026-08-08）：本条由 `bundle-launch` 起草，我收进来时只加了 `e2e-record`
> 那一例与「跳过不许渲染成成功」一条 —— 那是同一个形状最便宜的发作方式，
> 而它已经真的发生了。

## 12. `git diff --cached` 只在你检查的那一瞬间为真

**索引是所有 agent 共享的一份机器级状态。** 本条由 `e2e-record` 用一次真实事故换来:

> 他做了当时纪律要求的每一步 —— 逐 hunk `git apply --cached`、提交前核对 `git diff --cached --name-only`
> 干净 —— **然后在核对与 `git commit` 之间,另一位提交了,索引被重置。**
> 结果那次提交**丢了他自己的工作,还夹带了对方两个 hunk**。

**所以"逐文件 stage + 提交前核对全量 `--cached` 列表"是不够的。** 它防的是"我 add 多了",
防不住"**在我这两条命令之间,世界变了**"。这是 §11 的同族:**一个在检查那一刻为真的结论,
不等于在你据此行动那一刻仍然为真。**

规则:

- **用 `git commit -- <pathspec>` 提交**,而不是"先 stage 再 commit"。
  pathspec 让"提交哪些文件"和"提交"成为**同一个动作**,中间没有可以被别人插进来的窗口。
- **提交之后立刻 `git show --stat` 复核**:文件列表是不是恰好是你要的。
  **不是提交前核对,是提交后核对** —— 只有提交后的那份是既成事实。
- **撞到夹带时不许 revert 对方的 hunk** —— 那会把别人的工作从 master 上删掉。
  正确做法是:保住自己的、**在回执里声明对方的作者身份落在了你的提交里**,并告知 Manager。
- 工作区有别人在途改动时,**门禁跑在隔离 worktree 检出你自己那个 commit 的树上**。
  ⚠️ 共享 `node_modules` 里的 `@openmemo/*` 软链**会把别人未提交的改动漏进你的隔离环境**
  （`e2e-record` 实测撞到过）—— 需要把那些链接重新指到你自己的树。

**判据**:你据以行动的那个事实,必须在**行动的那一刻**仍然成立;做不到就把检查和行动合并成一个动作。

## 13. 裁完之后回去改原文，是一个会被静默跳过的步骤

**本轮四次同形**,所以它进协议:

| 原文                                            | 实际状态                                                                     | 烂了多久           |
| ----------------------------------------------- | ---------------------------------------------------------------------------- | ------------------ |
| `ADR-003` 决策 4:daemon 会清 macOS quarantine   | 全仓零 `xattr`;**有人早就发现了,只在 workflow 里挂了个 ⚠️,ADR 原文一字未动** | 约半个月           |
| `ADR-002:24`:`@blocknote/xl-*` (GPL-3.0) ✅允许 | 该包**从未被采用**,而这行留着等于给未来的人一张引入 GPL 的通行证             | 建仓至今           |
| `D-17 §5`:命令行 `tar` 能避开 quarantine        | **实测是错的**,`tar` 和归档实用工具都会传播                                  | 直到被真机实测撞破 |
| `D-03` 的 4 处「请裁决」                        | **`ADR-010` 决策 2 早就裁了**,`D-01` 也订正过,只有 `D-03` 原地不动           | 约 3 个月          |

**共同形状**:结论产生了、也被记在了**某个地方**,但**产生结论的那份原文没有被回去改**。
于是下一个人读到的是旧的那份,**而且它看起来仍然是活的**(还挂着"请裁决"、还写着"✅允许")。

**在别处挂警告不叫修** —— 那只是把不实**搬到了一个更少人读的地方**。

规则:

- **裁决落地 = 改原文 + 记依据,两件一起做完才算完。** 只做后半件的,视为没做。
- **原文用删除线保留,不许删** ——「此前写着什么」是可追溯性的一部分,
  而且能让下一个人看出"这里被改过、为什么改"。
- **写清「何时、被谁、依据什么」**。`ADR-003 §7.6` 与 `D-17 §5.1` 是格式先例。
- **谁发现原文不实,谁就地改** —— 哪怕那份文档不是他的地盘。
  发现的人手里有证据,而"等它的主人来改"就是上面那张表的成因。
  越界要在回执里申报,由 Manager 追认(本轮已有两次先例,都追认了)。
- **`docs/**` 与 `docs/adr/**` 归 Manager** —— 但上一条优先:**宁可越界改对,不要守界烂着。**

**判据**:一份文档里任何"待裁决 / 待办 / 未验证"的标记,都必须**今天仍然为真**。
它为假的时间,就是它在误导人的时间。
