## 一、回报重点：那两个按钮点下去实际发生了什么（控制台 / 网络 / DOM 三样）

### ①「去安装模型」—— **复现了，而且是真的死按钮**

```
存在=true  可见=true  禁用=false  文案="去安装模型"
点击成功=true
URL 变了=false   DOM 变了=false   /api 请求 0 条   控制台异常 0 条

```

三样现场**全是空的** —— 这正是它最难查的地方：不报错、不变灰、控制台干干净净。

`/models` 上**（`ModelsPage` 用了它）。**导航到你已经在的那一页 = 什么都不发生。**
不是事件没绑上，也不是 JS 抛了异常 —— 是这个按钮**在这一页上没有意义**。

### ②「立即测速」—— **在 Linux 上没能复现**，如实报


它是**有反应**的。我又追了一步，测它**失败时**是不是静默（因为

用路由拦截把该端点注入 500（**不改产品源码**），结果**界面上确实出现了可见的错误提示**。

所以「测速没反应」这一条我**没有复现**，标 `[未复现]`。剩下的可能性我不去猜，只列出来：

- **Windows 特有**（用户在 Windows，我在 Linux 跑的）`[未验证]`；
- 用户当时处在某个我没构造出来的状态（例如源列表为空 / 网络不通导致请求长时间挂起，
  按钮进入 `disabled={probe.isPending}` 后**看起来像没反应**）`[未验证]`；
- ⚠️ 顺带查到一条相关事实：`apps/daemon/src/http/sourcesRest.test.ts` 里
  **有 2 条测试在 master 上就是红的**（`/api/models/sources` 的 available 与"选一个源要记住"）。
  它与「测速」是同一块功能。**我没有动它**（不是我的文件），但建议一并派人看。

## 三、回报重点：变异证明结果

判据是"这条腿必须能在按钮死了的时候真的红"。做法：给目标按钮挂一个**捕获阶段**监听器，
`stopImmediatePropagation()` + `preventDefault()` —— 按钮**还在、还可见、还可点、样式不变**，
但点击到不了任何处理器。**产品源码一个字节没改**（§10）。

```
正常：  「立即测速」 URL 没变 / DOM 变了 / 1 个 /api 请求  → 有反应 = true   ✔ B1 通过
变异后：「立即测速」 URL 没变 / DOM 没变 / 0 个请求 / 0 异常 → 有反应 = false → **B1 如期变红**
```

**这条腿看得见"按钮死了"。** 反过来说：如果它没红，我这条腿就是在用一个看不见问题的
判据去证明没问题 —— 那比没有这条腿更糟。

## 五、这条腿的取舍（写下来，免得被当成偷懒）

**只跑 ubuntu，不铺三平台。** 它抓的是「按钮有没有反应」，那是**前端代码**的性质 ——
同一份 JS 在三个平台跑同一套逻辑。用户在 Windows 撞见，但成因与操作系统无关，
`[实测]` 在 Linux 上一模一样地复现了。铺三平台会让一条几分钟的腿变十几分钟，换不到新事实；
而真正与平台有关的那些，本来就在无头浏览器能力之外。

**刻意不追求覆盖所有页面**（Manager 交代）。贪多会让它慢到没人跑，
一条没人跑的腿等于没有。先钉住"点击 → 有反应"。

**已知未修的死按钮用清单钉住，不是删掉也不是一直红**：
出现清单之外的死按钮 → 红；清单里的被修好了 → 也红（提醒划掉）。
理由是本仓吃过的那个亏：**一个永远红的门禁等于没有门禁**。

### 二、门禁的洞（这条最重要）

**在 `/root/memo` 里跑 `pnpm -r test`，测的不是 master，是
「master + 当时所有 agent 未提交改动的并集」。** 那个并集**谁都没有承诺过它是绿的** ——
它甚至不对应任何一个存在过的 commit。

所以：

- 那里**红**，不能归给 master，也不能归给任何一个人；
- 那里**绿**，同样不能证明 master 是绿的。

`[实测]` 此刻（我写这份回执时）在共享树里跑 web 组件测试，得到的是**另一条**红：
`errors.NOT_IMPLEMENTED.detail` 缺失。追下去是**另一位正在进行中的改动** ——
`git diff` 显示 `zh-CN.json` / `en.json` 里新加了 `"NOT_IMPLEMENTED": {` 而
`detail` 还没补完，同时 `ModelDetailPage.tsx` 也改了 17 行（都**未提交**）。
那位正在做「测速/删除不可逆/文件夹改名」，写到一半是完全正常的。
**你看到的 `ERR_MODULE_NOT_FOUND` 与我看到的这条，是同一个机制的两次发作**：
两次都是**别人代码写到一半时被我们的命令撞见了**。

这与 PROTOCOL §10 / §12 是同一族的第三面：

| | 问的是 |
| --- | --- |
| §10 | 在最坏的那一秒，**别人看到的是什么？** |
| §12 | 我据以行动的事实，**在行动那一刻还成立吗？** |
| **本条** | 我这次跑出来的红，**到底是谁的代码给的？** |

§12 已经写了「工作区有别人在途改动时，门禁跑在隔离 worktree 上」，
**但没有任何东西会告诉你此刻工作区是脏的** —— 你得自己记得去看。
一条要靠人记得的规则，等价于一条迟早会被违反的规则（PROTOCOL §7 补充的老话）。

**建议的结构性补法（我没有实施，因为它要动共享的 `package.json`，
